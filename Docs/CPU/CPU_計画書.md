## 1. 決まったこと（2026-11-15 の質問の答え）

| 項目 | 決定 |
|---|---|
| 使い道 | 1人〜少人数で遊ぶ／開発・調整用の自動プレイ（4席すべて CPU） |
| 強さ | 3段階（やさしい／ふつう／つよい）。**画面では選ばない**（設定・起動オプション・エディタだけ。ゲームの初期値は「ふつう」） |
| 慣れて強くなる | 前のウェーブの**自分の成績（失敗）を振り返り、苦手な所から直す**。上限あり |
| 伸び幅 | 段階ごとに幅を持つ（やさしい＝初心者→少し慣れた人、つよい＝上手い人→とても上手い人。段階どうしは重ならない） |
| 持ち越し | **1試合の中だけ**。試合が始まるたびに「チュートリアルを終えたばかり（最低限の遊び方は分かっている）」に戻る |
| 公平さ | **人間と同じ条件**: その席のカメラに映る範囲だけを見る・反応に遅れがある・握る強さが少しぶれる |
| やること | 狙って撃つ・熱の管理／スキル・スマッシュボール／倒れた味方を助ける・自力で抜け出す／歯みがきタイムに参加／**移動する** |
| 協力 | 基本は「手薄な方向・誰もやっていない役を埋める」。ただし展示は「協力してクリアを目指しつつ、個人スコア1位も狙う」遊び方なので、**CPU も両方の塩梅をうまく取る** |
| 席 | キャラ選択で空いている席は CPU。**誰かが来たら入れ替わる**（試合中も）。開発中に**ステージのシーンだけで実行しても CPU が入る** |
| 入れ替わり | 来た人は CPU の**キャラ・場所・熱・スキルの溜まり・撃破数をそのまま引き継ぐ** |
| キャラ | 人が選ばなかったキャラから自動 |
| 画面の表示 | **ゲーム中は何も出さない**（人間と区別しない）。中身を見るのは開発用の表示だけ |
| 開発ツール | 専用の調整スタジオ／早送りで何試合も回す／結果を表（CSV）に残す／通信・性能テストに使う |

## 2. CPU の形（拡張しやすさのための分け方）

CPU 1人を、人間と同じ「目 → 頭 → 手」に分ける。**ゲームの側は「握力」と「移動の入力」しか受け取らない**ので、CPU はゲームのルールを特別扱いせず、人間と同じ入口から遊ぶ。

```
  目（CpuSenses）           頭（CpuBrain）                         手（CpuHands）
  その席のカメラに映る物  →  やりたいことの候補を採点して1つ選ぶ  →  握る強さ・握る/離す・移動の向き
  を、反応の遅れつきで見る    （候補 = 行動の部品。足すだけで増える）     人間の手のぶれ・限界つき
           ↑                          ↑
     上手さ（CpuSkillProfile）   学び（CpuLearner）: ウェーブの合間に振り返って上手さを上げる
```

### 2-1. 目（CpuSenses）
- その席のプレイヤーの画面に映る範囲（`FortressCameraRig` と同じ計算。画面を回した視点も同じ）だけを見る。
- 見る物: 群衆の敵の分布（混み具合・近さ・コアへの近さ）、爆弾の敵、スマッシュボール、破壊可能物、味方の砲台（倒れている・汚れている）、コアの HP、自分の熱・スキルの状態、ウェーブ・歯みがきタイムの様子、撃破数（チーム・自分の順位）。
- **反応の遅れ**: 見えた物は「上手さ」の反応時間だけ遅れて頭に届く（過去の様子を少し溜めておく）。
- 3万体を毎フレーム調べると重いので、群衆は**粗いマス目（扇形の向き × 距離）に数えたもの**を1秒に5〜10回作る（群衆の既存のマス目 `SwarmSpatialGrid` を読むだけ。新しい通信は無し）。

### 2-2. 頭（CpuBrain）＝行動の部品を採点して選ぶ
- 行動は1つずつ部品（`ICpuBehavior`）にする。各部品は「今これをやる価値は何点か」と「やるなら手をどう動かすか」を持つ。
- 頭は1秒に5〜10回、全部品に点を付けさせ、一番高いものを選ぶ（すぐ切り替わってガタガタしないよう、今の行動には少し点を足す）。
- **新しい行動を足す = 部品を1つ書いて、設定アセットの一覧に入れるだけ**。頭やゲームの側は直さない。

最初に作る部品:

| 部品 | 何をするか |
|---|---|
| 撃つ（Shoot） | 自動で回る砲身が「敵が多い向き」に来るのを読んで握り始める。撃つと回転が遅くなるのを使って、混んだ所をなめる。握る強さで太さと熱を加減する |
| 冷ます（CoolDown） | オーバーヒートしそうなら、敵の少ない向きの間に離して冷ます（上手いほど「次の山」に合わせて冷ます） |
| スキル（UseSkill） | 「使える」になったら、すぐ撃たずに良い時を待つ（次の撃ち始めがスキルになる仕組み）。**色ごとの判断部品**: 赤＝極太レーザーの線上に敵が多い時、青＝順番に撃てる向き、黄＝跳ね返りで敵の固まりに届く時、緑＝自分の周りに敵が寄っている時。待ちすぎたら妥協して撃つ |
| スマッシュボール（SmashBall） | 見えているボールに砲身が向く時に握る。移動で近づく・射線に入る |
| 救助（Revive） | 倒れた／汚れた味方に砲身が向く時にビームを当てる（`TurretDownSystem` の「味方のビームで回復・復活」）。誰も助けに行っていない時ほど点が高い |
| 抜け出す（Struggle） | 自分が倒れたら、にぎにぎで抜け出す（上手さで連打の速さが変わる） |
| 歯みがき（Brushing） | 歯みがきタイムで小刻みに握る。上手いほど人間とシンクロを合わせる |
| 移動（Move） | 行き先を決める部品。敵に囲まれない所・自分の担当の方向が見える所・ボールや倒れた味方の近く。壁は既存の当たり判定に任せる |

### 2-3. 手（CpuHands）＝人間と同じ入口
- 握力: `LaserTurret.GripSourceOverride`（`ITurretGripSource`）に「CPU の席は CPU の手、それ以外は今まで通り」を返す入口を差し込む。倒れたときの連打（`TurretDownSystem`）もこの入口を読んでいるので、そのまま効く。
- 人間らしさ: 握る強さは急に変わらない（握り込む／緩める速さに限界）、少しぶれる、1秒に握れる回数に上限。
- 移動: 移動の係（`TurretMoveDirector`）は今「この PC の人の砲台」だけを動かすので、「**この PC が動かす CPU の席**」も同じ計算（加速・壁・敵に押される）で動かせるようにする。

### 2-4. 上手さ（CpuSkillProfile）と3段階
上手さは「分野ごとの 0〜1 の慣れ」で持つ。0 = チュートリアルを終えたばかり、1 = その段階の上限。

| 分野 | 低い時 | 高い時 |
|---|---|---|
| 反応 | 見えてから動くまで遅い（例 0.6 秒） | 速い（例 0.15 秒） |
| 狙い | 敵が多い向きを見誤る・握り始めが遅れる | 砲身が来る少し前から握り始める |
| 熱の読み | よくオーバーヒートする | 山に合わせて冷ます |
| スキルの判断 | 使えたらすぐ撃つ | 一番効く時まで待つ |
| 周りを見る | 自分の前だけ | 倒れた味方・ボール・手薄な方向に気付く |
| 動き | あまり動かない・囲まれる | 先回りして良い場所に立つ |
| 歯みがき | 一定のリズム | 人間に合わせてシンクロ |

3段階は「各分野の値の**幅**（0 と 1 のときの実際の値）」を変えるだけ。数値はアセット（`CpuLevelProfile` × 3）に入れ、スタジオで調整する。

| 段階 | 0（試合の始め） | 1（上限） |
|---|---|---|
| やさしい | 初めて遊ぶ人 | 少し慣れた人 |
| ふつう | 少し慣れた人 | 上手い人 |
| つよい | 上手い人 | とても上手い人 |

### 2-5. 学び（CpuLearner）＝ウェーブごとの振り返り
- ウェーブの間、自分の出来事を記録する: オーバーヒートの回数、撃ったのに当たらなかった時間、スキルの効き（スキルで倒した数）、倒れた回数、助けに行くのが遅れた時間、取り逃したボール、歯みがきのシンクロ率 など。
- ウェーブの合間（`FortressWaves` の合間のお知らせ）に振り返り、**失敗が多かった分野ほど大きく慣れを上げる**（上手くいった分野も少しずつ上がる）。1ウェーブで上がる量にも上限を付け、急に別人にならないようにする。
- 慣れの上がり方はステージのウェーブ数（`WavePlan`）から決め、「最後のウェーブあたりで上限に近づく」ようにする（ウェーブ数が違うステージでも同じ感覚）。
- 試合が始まるたびに 0 に戻る。乱数の種を決められるようにし、自動プレイで同じ試合を再現できるようにする。

### 2-6. 性格（協力と個人スコアの塩梅）
- 各 CPU は「協力の重み」と「個人スコアの重み」を持ち、行動の採点に混ぜる。
  - コアが危ない・味方が倒れている・誰も守っていない方向がある → 協力の重みが上がる。
  - 余裕がある → 敵の多い所・ボールを取りに行き、撃破数を稼ぎに行く。自分が最下位なら少し欲張り、1位なら少し譲る。
- CPU ごとに少しずつ性格を変え（欲張り／世話焼き など）、4人が同じ動きにならないようにする。
- この塩梅は文章だけでは決めにくいので、**作る前に比べるページを作って選んでもらう**（いくつかやり方があるときは、先に見本を比べて選ぶ決まり）。

## 3. ゲームのどこにつなぐか（調べた結果）

| つなぐ所 | 今の作り | やること |
|---|---|---|
| 握力 | `LaserTurret.GripSourceOverride`（Host では `TurretNetworkHub` が全員分を返す。オフラインは null で `GripInputBridge` を直接読む） | 「CPU の席だけ差し替える」入口を足す。CPU は **Host（オフラインなら自分）だけで動かす** |
| 倒れたときの連打 | `TurretDownSystem` は `GripSourceOverride` を読む | そのまま効く（確認だけ） |
| 歯みがきタイム | `BrushingRunner` は各 PC のセンサーを直接数えて Host に送る | Host が CPU の席の分も数えられる口を足す |
| 移動 | `TurretMoveDirector` は自分の砲台だけ動かし、位置を `TurretMoveNet` で配る | Host が CPU の席も動かし、同じ仕組みで配る |
| キャラ選択 | 全員が決めたら開始（`GameSession.CharacterSelect`） | 空いている席を CPU として「決定済み」にし、残ったキャラを割り当てる |
| 途中参加 | 空いている一番小さい席に入る（`AutoMatchRules.FirstFreeSeat`） | CPU の席は「人が入れる席」として扱い、人が入ったら CPU を止めて引き渡す。熱・スキル・撃破数は Host が持っているのでそのまま残る。**位置だけ**は渡し方を決める（CPU の最後の位置から始める） |
| ステージのシーンだけで実行 | `TurretMoveDirector` と同じく起動時に自動で作られる係にする | 通信していないときは「自分以外の席は CPU」（設定で切り替え） |
| 撃破数・順位 | `EnemyKillCounter.ByPlayer` | 性格の判断に読むだけ |

ゲーム中の画面には何も出さない。開発用の「頭の中」表示は F9 の仲間（デバッグ表示）に入れる。

## 4. 開発用の道具

1. **起動オプション**（.exe・bat 用）: `-cpu 2,3,4`（CPU にする席）、`-cpu-all`（全席）、`-cpu-level easy|normal|hard`、`-cpu-seed N`、`-autoplay N`（N試合を自動で回す）、`-timescale 2` など。
2. **自動プレイ**: 全席 CPU で試合を回し、リザルトが出たら自動で次の試合へ。早送りあり。
3. **結果の表（CSV）**: 試合ごと・ウェーブごとに、撃破数（各自）、コアの HP、倒れた回数、オーバーヒート、スキルの効き、各分野の慣れ。段階ごとの強さの比べや、ステージの難しさの調整に使う。
4. **頭の中の表示**（Play 中、F9 系）: 各 CPU が今選んでいる行動と点数、見えている範囲、分野ごとの慣れ。
5. **CPU 調整スタジオ**（エディタの専用ウィンドウ。`Tool_UI_Analysis.md` に従い**最初に見える項目は少なく**）:
   - 最初の画面: 段階の選択（やさしい／ふつう／つよい）と、分野ごとの「始め → 上限」のつまみだけ。
   - 「試合を回す」: 何試合・早送り・段階を選んで実行 → 結果を並べて比べる。
   - 「頭の中」: Play 中の各 CPU の様子。
   - 細かい数値（行動ごとの点の付け方など）は「詳しく」の奥へ。
6. **通信・性能テスト**: 今の bench の bat に、各 PC の席を CPU にするオプションを組み合わせる（人がいなくても4台で本番に近い負荷）。

## 6. 気をつけること

- **早送り**: 移動などは `Time.unscaledDeltaTime` を使っている所があるので、早送りすると CPU とゲームの時間がずれる。早送りの前に、どこが「実時間」で動いているかを洗い出す。
- **重さ**: CPU の「目」は Host で4人分動く。群衆はマス目の数を読むだけにし、1秒5〜10回に抑える。展示の Host PC の負荷を bench で確かめる。
- **移動は実験中のブランチ**: 移動が main に入らない場合に備え、「移動」部品は外せるようにしておく（外すと席から動かない CPU になる）。
- **人間と同じ条件**: カメラの外の情報を使わないよう、目以外から敵の情報を読まない作りにする（頭が直接 `SwarmSystem` を読まない）。
- **資料**: ツールの資料（`Docs/Tools/`）は頼まれたときだけ作る・直す決まりなので、この計画書以外は作らない。
