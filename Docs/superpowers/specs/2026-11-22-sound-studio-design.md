# サウンドスタジオ（SE を入れるツール）

2026-11-22。見本ページ: https://claude.ai/artifact/WnSvkycXUUvjXL2NTh3exS （ユーザーは A「2つに分けた一覧」を選んだ）

## ねらい
- サウンド担当（プログラミングは超初心者）が、ゲームのどこで音が鳴るかを遊ぶ流れの順に見て、音を入れ、音量を合わせ、試聴できるようにする。
- 今は音を入れる欄（`FortressEffect`）が約108か所あるが、設定ファイル・シーン・スキルの設定などに散らばっていて、どこにあるか分からない。音の素材も13個ほどしかない。
- 失敗の条件: サウンド担当がツールを開いて「どこを触ればいいか」「入れた音がどこで鳴るか」で手が止まること。コードを読まないと音を入れられないこと。

## やること・やらないこと
- やる: 新しいエディタの窓「サウンドスタジオ」（メニュー `Tools/サウンドスタジオ`）。今ある全部の欄を流れの順に並べ、音を入れる・選ぶ・試聴する・音量を合わせる。
- やる: 欄ごとの音量の倍率と「鳴らすPC」を、ゲームが実際に使うようにする（`FortressEffect` に項目を足し、`FortressEffectPlayer` で使う）。
- やる: wav を窓へドラッグすると、D-Drive の素材フォルダへ入れ、SE として登録され、その欄に入るまでを自動でする。
- やる（2段目）: まだ欄がないタイミングに、鳴らす所をコードに足す（見本ページの候補 N1〜N20 の全部。ユーザー決定）。BGM が試合にしかないので、ほかのシーンの BGM もこの段で足す。
- やらない（ユーザー決定）: エフェクト（VFX）はこのツールでは扱わない。後で足すかもしれないので、足しやすい作りにはしておく。欄の VFX はそのまま残し、ツールから消したり変えたりしない。
- やらない: D-Drive のパッケージは改造しない。`.unity` `.asset` をテキストで直接書き換えない（Unity の API で変える）。ツールの資料（`Docs/Tools/`）は作らない（CLAUDE.md の決まり。頼まれたら作る）。

## 案の比較（ユーザーは A を選んだ）
- **A 2つに分けた一覧（採用）**: 左に流れの順のシーン、右にそのシーンのタイミングの一覧。1行は「名前・音・音量・▶」だけ。行を選んだときだけ、下に細かい設定が出る。初めてでも迷いにくく、最初に見える物が少ない（使いやすさの資料の T2）。
- B 時間の線: 起きる順に点を並べ、通して試聴できる。試合はタイミングが多く、いつ起きるか決まっていない物も多いので、点が混み合う。
- C ミキサー: 縦のつまみで音量を見比べやすいが、名前が読みにくく、初めての人には何の画面か分かりにくい。

## ユーザーが決めたこと
- 使う人: サウンド担当の超初心者プログラマー。言葉はやさしく、プログラムの言葉（クラス名・フィールド名）は画面に出さない。
- 並び: 遊ぶ流れの順（タイトル → ロビー → キャラ選択 → 遊び方 → ステージ抽選 → ステージ登場 → 試合 → ボス → 結果）。
- タイミング: 今ある欄に加えて、まだ欄がないタイミングも候補として出す。
- 音量: 音ごとの音量（D-Drive の SE の Volume。その音を使う所すべてに効く）と、欄ごとの「この場所だけ」の倍率の両方。
- 鳴らすPC: 欄ごとに選べる。みんなに起きる事（ウェーブ開始など）は全員のPCで鳴らす。
- 素材: wav をドラッグしたら D-Drive への登録まで自動。
- 扱う物: SE・声・BGM を同じツールで。エフェクトは今は扱わない。
- 2段目で作る候補: N1〜N20 の全部。
- 「その人の事」の音（自分のレーザーなど）は、最初は「その人のPCだけで鳴らす」。
- CPU の「その人の事」の音は Host のPCで鳴らす。ただし本番では CPU を使わないので、ここは手間をかけなくてよい（壊さなければよい）。

## 画面（StudioKit の StudioShell を使う）
- **上の帯**: 題名、「音あり N / M」、［音がない所だけ］の切り替え、SE 全体・声全体・BGM 全体の音量（0〜1）。
- **左のナビ**: 最初に「はじめに」（使い方3行と、素材の数・音がない欄の数）。その下に流れの順のシーン、最後に「その他（まだ分けていない欄）」。各シーンの横に、音がない欄の数を黄色で出す。
- **右（シーンのページ）**: 上にそのシーンの BGM の行（今ある BGM の欄: 試合の `FortressBgmPlayer`、ロビーの `GameSession.lobbyBgm`（今は空）、ステージごとの BGM（`StageSet`、`StageRoot` が鳴らす））。BGM の行は、曲の選択・曲そのものの音量・試聴だけ（倍率と鳴らすPCは出さない）。上の帯に BGM 全体の音量も出す。その下にタイミングの行を、小見出し（例: 試合 › 試合の進行／レーザー／敵・コア／スキル／席替え・歯みがき）でまとめて並べる。
  - 1行: 名前（その人の事なら「その人」の小さな印、声なら「声」の印）・音（なければオレンジで「音を入れる…」）・音量のバー・▶。
  - 同じ欄を持つ設定ファイルが複数あるとき（4人分のレーザーの設定、壊せる物の種類ごと、スキル4色など）は、行の名前の後ろに持ち主の名前を小さく出すか、1行にまとめて「4つの設定で同じ音」と出す。
  - まだ欄がない候補は紫の点線で出し、「コードを足すと使えます」とだけ書く（2段目で本物の行になる）。
- **行を選ぶと下に出る細かい設定**:
  - 音そのもの（この音を使う所すべてに効く）: 音量・高さのばらつき（`PitchRange`）・連打の間引き（`CooldownSec`）・同時に鳴る数（`MaxConcurrent`）。
  - この場所だけ: 音量の倍率（0〜1、初期値1。「ここだけ小さめ」にするための物。もっと大きくしたいときは音そのものの音量を上げる。Unity の音量は1が上限なので、1より上は効かない）・鳴らすPC（「その人のPCだけ／全員のPC」。みんなに起きる事の欄は「全員のPC」と表示だけで、切り替えは出さない）。
  - 同じ音を使っている所の一覧（押すとその行へ飛ぶ）。
  - ボタン: ［別の音を選ぶ］（検索付きの一覧）・［音を外す］・［D-Drive で開く］（SE の専用エディタ）・［設定のある所を見せる］（Project でその設定ファイル／シーンの物を選ぶ。作る人向け）。
- **下の帯**: マウスを乗せた物の説明（StudioKit がもともと持つ仕組み）。
- 初期値（音なし・倍率1・全員のPC）から変えた所に印を付け、右クリックで戻せる（T4）。

## 動き
- **試聴（▶）**: Play していなくても鳴る。音の音量・高さのばらつき・この場所の倍率・全体音量を掛けて鳴らす。Play 外では D-Drive の `Audio` がまだ動いていないので、D-Drive のエディタ用の試聴（`Editor/Preview/PreviewService`）を使う（使えなければエディタだけの試聴の係を作る）。Play 中は、ゲームと同じ道（`FortressEffectPlayer`）で鳴らす。
- **Play 中に鳴った行を光らせる**（Claude の提案）: ゲームでその欄が鳴ったら、ツールの行とナビのシーンが少し光る。鳴るはずなのに鳴らない欄が分かる。エディタだけの仕組みで、ビルドには入れない。設定ファイルの欄は鳴った `FortressEffect` がそのまま同じ物なので見分けられる。シーン・Prefab の欄は Play 中は複製なので、鳴らした部品と欄の場所（持ち主の型と欄の道筋）で行を探す。
- **wav のドラッグ**: 行（または「はじめに」の素材置き場）に wav を落とすと、英字の名前を聞く小さな窓が出る（初期値はタイミング名から作る。例 `Start`）。`Assets/_Game/DDrive/SourceAssets/Se/<シーンのフォルダ>/` にコピーする（フォルダ名も番号札の名前に入るので、名前にシーン名を重ねない。例 `Se/Title/Start` → `SEID.TitleStart`）。D-Drive の登録は取り込みの少し後（`delayCall`）に走るので、登録された SE ができるのを待ってからその欄に入れる。欄には番号そのものが入るので、`SEID` の作り直しは欄のためには要らない（一覧の名前を新しくするために、後でまとめて呼ぶ）。同じ名前があれば上書きするか聞く。
- **保存**: 設定ファイル（ScriptableObject）の欄は、変えたらすぐ保存する（Undo で戻せる）。シーンにある欄は、そのシーンを裏で開いて変え、保存して閉じる。そのシーンがすでに開いていれば、その場で変えて「シーンを保存してください」と出す。Play 中はシーンにある欄は変えられない（止めると消えるため）と出して触れなくする。
- **ゲーム側の変更**:
  - `FortressEffect` に「この場所だけの音量の倍率」「鳴らすPC」「声かどうか」を足す。初期値は今の動き（倍率1・全員のPC・声ではない）と同じにして、今ある設定は何も変わらない。「声かどうか」はツールが名前の表を見て入れる（ゲームはエディタの表を読めないため）。
  - `FortressEffectPlayer.PlaySound` に「誰の事か」（プレイヤー番号）を渡せるようにする。「その人のPCだけ」の欄は、その番号が自分（`FortressNetworkBootstrap.Instance.LocalPlayerIndex`。ネットにつながっていないときは -1）でなければ鳴らさない。1人で遊ぶとき・番号が分からないときは鳴らす。その番号が CPU の席なら、Host のPCで鳴らす（どの席が CPU かを調べる一番簡単な方法でよい）。今は番号を渡していない呼び出しが多い（レーザーの撃ち始めなど。`PlayOnce` の番号は色付けにしか使っていない）ので、名前の表で「その人の事」にした欄の呼び出し（15ファイルくらい）に番号を渡すよう直す。
  - 倍率と全体音量は、鳴らした後に `DDriveRuntimeBootstrap.Instance.Audio.SetVolume(handle, 音量)` で掛ける（`Audio` の窓口には無く、中の係にある。今の音量を読む方法がないので、SE の `Volume` を D-Drive の一覧（Registry）から読んで掛け算する）。連打の間引き中は鳴らずに無効な Handle が返るので、そのときは何もしない。
  - SE 全体・声全体・BGM 全体の音量は、小さな設定ファイル（音のバランス）に持ち、`FortressEffectPlayer`・BGM を鳴らす所で掛ける。今はミキサー（AudioMixer）がプロジェクトにないので、それを作らずに済む形にする。

## 作り（Claude が決めた所）
- 置き場所: `Assets/_Tools/SoundStudio/Editor/`（エディタの窓）。ゲーム側の小さな変更は `Assets/_Game/Fortress/Runtime/Effects/` の中。
- 欄の見つけ方: プロジェクトの設定ファイル・Prefab と、ビルドに入っているシーンを調べ、`FortressEffect` の欄（と BGM の欄）を自動で集める。見つける作業は窓を開いたときと［調べ直す］を押したときだけ。
- 欄の名前と場所: 「どの設定のどの欄を、どのシーンのどの小見出しに、何という名前で出すか、その人の事か」を1つの表（コードの中の一覧）にまとめる。表にない欄は「その他」に、欄の説明（Tooltip）を名前にして出す。欄が増えたら表に1行足すだけで並ぶ。
- 窓は薄くし、部品ごとにファイルを分ける（窓・欄を集める係・名前の表・シーンのページ・行・細かい設定・試聴・wav の取り込み）。集める係と名前の表は、Unity の画面を使わずテストできる形にする。
- 確かめ方: Unity の csproj を dotnet msbuild でコンパイルし、テストが書ける所（名前の表・鳴らすPCの判断）はテストを書く。画面の動きは Unity でユーザーに確かめてもらう（今は UnityMCP がつながっていない）。
- ブランチ: main から新しいブランチを切って作る（今の作業中のブランチの変更は入れない）。ブランチ名は日本語にする（ユーザー決定。例 `サウンドスタジオ`）。

## 2段目（候補 N1〜N20 の全部）
- 選ばれたタイミングごとに、そのタイミングを持つ設定・部品に `FortressEffect` の欄を1つ足し、起きた所で鳴らすコードを1か所足す。名前の表にも1行足す。
- BGM（N17〜N20）は、シーンに BGM の係（`FortressBgmPlayer`）を置くか、ボス戦・結果で切り替える仕組みを足す。
- 1つのタイミングを1つのコミットにして、要らなければ戻せるようにする。

## 作る人に任せる所
- 各欄の名前と、どの小見出しに入れるか（見本ページの名前が土台）。
- 1つの欄を複数の設定ファイルが持つときの見せ方（まとめるか、分けるか）。
- 英字の名前の自動の作り方。
