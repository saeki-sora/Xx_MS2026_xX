## 1. ステージ案の読み取り

コンセプトは「上下の高低差があるステージ」。ゲームは真上から見る形（地図は XY 平面）なので、**画面の上下をそのまま「高い・低い」として使う**。

- 一番上に壁（タイル）の段がある。ここに敵の出口が2つある。
- その下にバスタブのふちがある。
  - 灰色の2本は壊れない。真ん中が空いていて、敵はここを通って下へ降りる。
  - ふちの上に P1（赤・左）と P2（青・右）がいる。
- コア（歯）は、真ん中の「ビームで崩れる橋」（緑の板）の上にある。
- 左右の中ほどにも敵の出口が2つある。
- 下の段（床の近く）に P3（緑・左）と P4（黄・右）がいる。
- **WAVE1〜2**：上の2人の負担が重い。上の出口からの敵は、ふちのすき間を通ってコアへ向かう。
- **WAVE3〜5**：橋が壊れて、コアが床まで落ちる。下の2人の負担が重くなる。
- 高低差による敵の偏りは、敵の量と種類で調整する。

プレイヤーの色は、いまのゲームの色（`FortressColors`：P1 赤、P2 青、P3 緑、P4 黄）と同じ。

> **注意（絵について）**：資料の図のバスタブの絵は、Adobe Stock の透かしが入った他の人の素材だった。ルール（CLAUDE.md の「UI デザインの参考サイト」節）のとおり、使うのは「どこに何を置くか」だけにする。絵の見た目を見本にはしない。透かし付きなので、ゲームの中にもそのまま使えない。

## 2. 決まったこと（ユーザー決定 2026-10-21〜22）

| 項目 | 決定 |
|---|---|
| 橋の壊れ方 | ビームで削れて壊れることもある。**WAVE3 が始まった時点でまだ残っていたら、自動で崩れる** |
| WAVE の区切り | **番号つきの WAVE の仕組みを新しく作る**。画面に「WAVE 3」と出す。全部のステージで使える共通の仕組みにする |
| WAVE の進み方 | **そのWAVE で決めた数の敵を倒したら、次の WAVE** |
| クリア条件 | **今と同じ撃破数**（`FortressMatchRules.clearKills`）。コアが壊れたらゲームオーバーも今と同じ |
| バスタブのふち | 敵は通れない（真ん中のすき間だけ通れる）。**ビームは通り抜ける** |
| カメラ | **4人とも図と同じ向き**（上が壁、下が床）。ステージ2だけの設定にし、ステージ1は今のまま |
| ルーレットの名前 | **「お風呂場」**。説明は「橋が崩れるとコアが落ちる」（あとから変えられる） |
| 見た目 | **今回は仮の箱で進める**。絵はチームが作ったら、ステージ背景スタジオや壊れる障害物の見た目欄に入れ替える |

### 撃破数で進む WAVE とクリア条件の関係

- WAVE は「そのWAVE の中で倒した数」が目標に届いたら次へ進む。クリアは「試合全体で倒した数」が `clearKills` に届いたとき。
- `clearKills` が WAVE1〜4 の目標の合計より少ないと、WAVE5 の前にクリアしてしまう。
- 要塞デザイナーには、目標の合計と `clearKills` を並べて表示する。WAVE5 に届かない設定なら警告を出す。
- 例：clearKills 200 なら、WAVE1〜4 の目標を 25 / 35 / 45 / 45（合計 150）にし、WAVE5 は残り 50 体でクリアになる。
- WAVE5（最後の WAVE）には次がない。クリアするまで、その時間割をくり返す。

## 4. 作業の順番

いまの `Stage2.unity`（Stage1 を左右反対にした仮のもの）は、中身を作り直す。1項目ずつ、元に戻せる単位でコミットする（コードとドキュメントを同じコミットに入れる）。

### 1. 地形とカメラ（`Assets/Scenes/Stages/Stage2.unity`）

- `[Stage] Content` の中身を作り直す。
  - 置くもの：出口4つ、ふち2本、バスタブの左右の壁、橋、`NavigationField`、`SwarmSystem`、`EnemySpawnDirector`。
  - `[Fortress] Match Rules` は残す。
- **ふちは「敵だけ止めて、ビームは通す」**：
  - 根拠：ビーム（`LaserBeamVisual`）は、トリガーの当たり判定を素通りする（`useTriggers = false`）。敵の道の計算（`NavigationObstacle`）は、トリガーかどうかに関係なく当たり判定の範囲を壁にする。
  - なので、ふちの `Collider2D` をトリガーにすれば、コードを変えずにできる見込み。
  - Unity で確かめる。だめなら、`NavigationObstacle` に「ビームを通す」印を足す小さな変更にする（要塞デザイナーの説明書も更新）。
- **橋**は「壊れる障害物」で作る。
  - 再生なし、体力はビームで数十秒削ると壊れる程度（仮）。
  - 壊れたときの演出は、いまの仮の破壊演出を使う。
- `StageLayout` の目印：コア＝橋の上、砲台4つ＝3章の位置。
- **ステージ2専用のカメラ視点**を作る（`CameraViewPreset_Stage2`）。
  - 全員が回転なし（roll 0）で、画面の上が壁、下が床になるようにする。
  - 全体が収まる位置と画角にし、遠近ありは今と同じにする。
  - `StageLayout.cameraPreset` に入れる。
- `Tools › ステージ › チェック` で、足りない物がないか確かめる。

### 2. WAVE の仕組み（全ステージ共通・新規）

いまの敵の出し方は「時間割（`EnemyWaveConfig`）を1本くり返す」だけで、WAVE の番号はない。これに WAVE の区切りを足す。

- **データ（新しいアセット `WaveSequence`、Create メニュー `Fortress/Wave Sequence`）**：WAVE ごとに次を持つ。
  - 時間割：いまの `EnemyWaveConfig` をそのまま使う。最後まで出し終わったら、そのWAVE の中でくり返す。
  - 次へ進む撃破数：このWAVE で倒した数が届いたら次へ。
  - 次の WAVE までの合間の秒数：敵を出さない休み時間。仮で 3 秒。
  - 始まりの演出：`FortressEffect`（VFX・SE の番号札）。
  - 表示名（空なら「WAVE n」）。
- **進める係（新しいコンポーネント `WaveSequenceRunner`、ステージのシーンに置く）**：
  - Host（とオフライン）だけが進める。
  - 撃破数は、いまの `EnemyKillCounter` の合計の増えた分で数える。
  - WAVE が変わったら、`EnemySpawnDirector` の時間割を差し替えて最初から出す。前の WAVE の残りの敵は消さない。
  - `WaveSequence` を置かないステージ（いまの Stage1）は、今までどおり時間割1本で動く。
- **通信**：
  - いまの試合の情報（`FortressMatch` が Host から全員へ送るもの）に、WAVE の番号と、そのWAVE で倒した数を足す。
  - Client は番号が変わったら、自分で始まりの演出と画面表示を出す（演出は各PCが自分で鳴らすルールどおり）。
  - 途中から入った人には、定期的な情報で今の WAVE が届く。
- **お知らせ（static イベント）**：`FortressWaves.WaveStarted(int wave)`。ステージの仕掛け（橋）や HUD が受け取る。全PCで鳴る。
- **画面表示（UIスタジオ）**：
  - HUD に「WAVE 3 / 5」と、次の WAVE までの撃破の進み具合（例：12 / 35）を出す。
  - WAVE が始まった瞬間に大きく「WAVE 3」を出す。
  - 置き場所は HUD の見本（コアのバーは上の真ん中）とぶつからない所にする。
- **要塞デザイナー**：「敵ウェーブ」タブに WAVE の一覧を足す。
  - 並べ替え、時間割の選択、撃破数、合間の秒数を編集できるようにする。
  - 撃破数の合計とクリア撃破数を並べて表示し、2章の警告を出す。
  - Play 中は、今の WAVE と倒した数を表示し、「次の WAVE へ進める」ボタン（テスト用）を置く。
- **テスト**：WAVE の進み方（撃破数、最後の WAVE のくり返し、合間）を、Unity なしで回る小さなテストにする。

### 3. 橋が壊れたらコアが落ちる（ステージ2の仕掛け、新しいコンポーネント `StageCoreDrop`）

- 置き場所：`Stage2.unity`。
  - 持つもの：橋（`DestructibleObstacle`）、落ちる先の目印。
  - 演出の欄：落ちる演出、着地の演出（どちらも `FortressEffect`）、着地の画面の揺れ。
- **橋が壊れたら（`Destroyed` イベント）、各PCでコアを落ちる先まで動かす。**
  - 重力っぽく速くなりながら落ち、着地で少し弾む（仮で約 0.8 秒）。
  - 橋が壊れたことは、いまの壊れる障害物の通信で全員に届く。Client でも `Destroyed` が鳴るので、コアの動きのために新しい通信は要らない。
  - 途中から入った人は、参加時の情報で `Destroyed` が鳴る。そのときはアニメなしで、すぐ落ちた位置に置く。
- **WAVE3 の開始時に橋が残っていたら、Host が橋を崩す**（`DestroyNow`）。
  - WAVE3 にしたのは、`StageCoreDrop` の設定欄「この WAVE で必ず崩す」の値（既定 3）。
- 着地したら、敵の道を計算し直す（`NavigationField.MarkDirty`）。敵は落ちたコアへ向かい直す。
  - 敵の行き先は、毎フレームのコアの位置を使っているので、そのまま付いてくる。
- 落ちている間も、コアはダメージを受ける（今と同じ）。
- 次の試合では、`StageLayout` がコアを橋の上の目印に戻す（いまの仕組みのまま）。

### 4. 敵の時間割（WAVE1〜5）

- 新しく作るアセット：`Assets/Stages/Data/Stage2/`
  - 時間割 `Stage2_Wave1`〜`Stage2_Wave5`（`EnemyWaveConfig`）
  - WAVE の一覧 `Stage2_Waves`（`WaveSequence`）
- **WAVE1〜2**：上の出口を多めに、横の出口を少なめにする。
- **WAVE3〜5**：横の出口を多めにする（上からの敵も、すき間を抜けて床まで降りてくる）。
- WAVE が進むほど、数を増やし、強い敵（ボス・爆弾）を混ぜる。
- 数と次へ進む撃破数は仮で入れる。調整は要塞デザイナーでプランナーができる。
- クリア撃破数（`[Fortress] Match Rules` の `clearKills`）は、2章の関係を満たす値にする。
  - いまの Stage2 は、分けたときに Stage1 の 1.5 倍（300）になっている。目標の合計に合わせて決め直す。

1. `Game` だけで Play（`Default Stage Index` を 1 にして Stage2）。
