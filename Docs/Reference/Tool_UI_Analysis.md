# 使いやすいツールの解剖（ツール・UI の判断の土台・AI 向け）

使いやすいと評判のツール（Figma・Blender・Unreal・Unity・Ableton Live・Procreate・Linear など）が作り直したときに何を考えたか、使いやすさの研究（Nielsen Norman Group、Laws of UX）、ゲーム開発ツールの UX の記事を集め、「見やすい・使いやすい」と感じる理由を10にまとめた資料。2026-11-09 に作成（ネットからの参考集めは、このときだけユーザーが許可。有料・会員限定の資料には登録も課金もしていない）。人間向けのページ（自作の比較実験付き）は https://claude.ai/artifact/KedGRvekAJ6jXv8jNiQCxE 。

きっかけ: ユーザーがスキル調整スタジオを「見づらい、ぱっと見で見える項目が多すぎて使いにくい」と言った（2026-11-09）。

- **読み方**: まず `[CHECK]` を読み、必要な節だけを `[TAG]` で `Grep` して `Read` する。

## 2. 10の理由

### T1. やりたいことで並べる [T1]
- **中身**: データの形（クラス・設定ファイルの区切り）ではなく、使う人の目的・作業の順番で並べる。名前も目的で付ける。
- **なぜ**: 人は「稲妻を少し弱めたい」と考えて画面を見る。並びが考えと同じなら、探す時間がなくなる。
- **根拠**: 設定画面で一番多い失敗は、システムの作りで並べること（実務指針、説）／よくある作業に何回クリックと画面移動が要るかを数えて比べ、数字は作業している場所に出す（Robin-Yann Storm、ゲームのエディタの UX、本人）／何を表に出すかは作業の調査と使われる回数のデータで決める（NN/g、本人）

### T2. 最初は少なく、残りは1段奥へ [T2]
- **中身**: よく使う少しの物だけ最初に見せ、残りは名前のはっきりした「詳しく」の奥に1か所にまとめる（段階的に見せる＝プログレッシブ・ディスクロージャー）。
- **なぜ**: 選択肢が増えるほど決めるのに時間がかかる（ヒックの法則）。最初の画面にある物は「大事」という合図になり、初心者は迷わず、慣れた人も読み飛ばす手間が減る。
- **根拠**:
  - NN/g: 最初は一番大事な少しだけ。奥への入口ははっきりした名前で。奥は 2 段まで（3 段以上で迷子）。入口は 1 つ（本人）
  - Figma UI3: よく使う操作が先に来るよう並べ直し、あまり使われない入力欄を減らした（本人）
  - Unreal 詳細パネル: 上級者向けの項目は最初は隠し、まとまりごとに開くボタン（本人）
  - Unity エディタの手引き（2017）: よく使う物を先に、上級者向けははっきりした操作の奥へ。よく触る物を折りたたみに入れない（本人）
  - Blender 2.80: 基本 1 列、細かい設定は折りたためる小枠（本人）
  - Unreal Niagara: 全部の設定とは別に、自分で選んだ項目だけの「Summary View」を作れる（本人）
  - Tweakpane 系の調整パネル: よく触る物は一番上、二の次は最初は閉じる（説）

### T3. 変えたらすぐ見える [T3]
- **中身**: 値を変えた瞬間に結果が見える。待ち時間・「適用」ボタンを挟まない。
- **なぜ**: 結果がすぐ見えると数字を「感じて」決められ、試す回数が増え、良い値に早く着く。
- **根拠**: 作る人は作っている物と直接つながっていなければならない、数字をドラッグすると絵がその場で変わる例（Bret Victor「Inventing on Principle」、本人）／今どうなっているかをすぐ知らせる（NN/g 10原則、本人）／速さそのものを機能として扱った（Figma、本人）／元に戻すと何を戻したかを短く出す（Procreate、本人）

### T4. 状態が見える [T4]
- **中身**: 初期値から変えた所に印、押せば初期値に戻る。効いていない項目は薄く。
- **なぜ**: 変えた所だけを確かめればよくなる。触っても変わらない所で迷わない。
- **根拠**: 変えた項目に印と初期値に戻すボタン、親スイッチが切れた項目は灰色（Unreal 詳細パネル、本人）／アニメーション・ほかの値で決まっているなどを印で表示（Blender 2.80、本人）／ほとんどの人は設定を変えないので初期値が体験を決める。変えた所は分かるように（実務指針、説）

### T5. 探さずに見つかる [T5]
- **中身**: 名前で絞り込む検索、よく使う物を手元に集めるお気に入り、最近使った物。
- **なぜ**: 「どこにあったか」を思い出すより名前の一部を打つほうが速い。
- **根拠**: 打つと合う項目だけに絞り込み、お気に入りは一番上へ（Unreal、本人。お気に入りは実験的機能）／Q キーで自分で集めた機能のメニュー（Blender 2.80、本人）／コマンドパレット・打ち込み検索で、探す操作を選ぶ操作に変える（Linear・Ableton Live、記事）／最近使った物・お気に入りで途中の作業に戻りやすい（NN/g、本人）

### T6. 覚えさせない、説明はその場で [T6]
- **中身**: 見れば分かる言葉のラベル。説明は短く、必要な所に、決まった場所に。
- **なぜ**: 思い出すより見て選ぶほうがずっと楽。長い説明書は読まれず覚えられない。
- **根拠**:
  - NN/g: 見て選べるように。アイコンには名前。長い手引きよりその場の短いヒント（本人）
  - Ableton Live: マウスを乗せた物の説明とショートカットを画面の隅の決まった場所に（記事）
  - Blender 2.80: 画面下の帯に今押せるボタン・キーの意味（本人）
  - Figma UI3: ラベルのないアイコンだけの案は分かりにくく読み上げにも困るので戻した（本人）
  - Unity エディタの手引き（2017）: 入力欄にはほぼ必ずラベル。略語を避ける。説明は 3 行以内の完全な文。8 割の人が説明なしで使えるなら説明枠は置かない。スイッチの名前に「有効にする」「使う」を付けない。ON で機能が止まるスイッチを作らない。2 つの状態の切り替えはスイッチでなく選択（本人）

### T7. 慣れた形に合わせる [T7]
- **中身**: ほかのツールで覚えた操作・並び順をそのまま使えるようにする。作り直すときは慣れを壊さない。
- **なぜ**: 覚えた操作は手が勝手に動く。並び順を変えるだけで慣れた人は遅くなる。
- **根拠**: 人はほとんどの時間をほかのサイトで過ごすので、同じように動くと期待する。作り直すときは戻せる期間を設ける（Jakob の法則、本人）／作る前に同じ問題をほかのソフトがどう解いているか調べ、理由なく操作を発明しない（Ubisoft の David Lightbown、本人）／幅・高さを上に移す案は手の動きを崩したので戻した。試験中は古い画面に戻せた（Figma、本人）／昔の操作のままにできる設定（Blender 2.80、本人）

### T8. 作品が主役、UI は控えめ [T8]
- **中身**: 作っている物（シーン・プレビュー）が主役。UI は控えめに、いつも同じ場所に。毎回は触らない物は小さく。
- **なぜ**: UI が作品と同じくらい目立つと目が疲れる。ただし勝手に消える・動く UI は場所が分からず不安になる。
- **根拠**: UI は最小限、描き始めると自動で隠す設定（Procreate、本人）／マウスを乗せた時だけ出る UI・勝手に隠れる枠は不安定に感じられてやめた。浮かぶパネルも作品を隠して遅くなるので固定の枠に戻した（Figma UI3、本人）／1 つの窓にすべて収め、枠はキーで出し入れ（Ableton Live、記事）／UI は中身を支え、張り合わない（Apple の手引き、記事）

### T9. 余白で分け、箱を重ねない [T9]
- **中身**: まとまりは並び（文脈）と余白で見せる。枠の入れ子、折りたたみの入れ子、中にスクロールする枠を作らない。
- **なぜ**: 枠が重なると線を読むことに力を使い、中身を読む力が減る。
- **根拠**: まとまりはまず並びで見せ、余白・見出しは足りないときだけ。項目の間 2pt、まとまりの間 10pt。見出しの下は字下げしない（字下げは折りたたみの中身だけ）。中にスクロールする枠を作らない。タブは 4 つまで。最小幅（275pt）で横スクロールしない（Unity エディタの手引き 2017、本人）／折りたたみの中に折りたたみを入れない。中の枠だけをスクロールさせない（Carbon、記事）／小さなまとまりに分ける（ただし「7 個」を言い訳にした制限はしない）（Miller の法則、本人）

### T10. 使う人を見て直す [T10]
- **中身**: 作る前に使う人の作業を調べ、作った後に使う様子を見て直す。
- **なぜ**: 作った人は慣れすぎていて迷う所に気づけない。小さな手間も毎日積み重なる。
- **根拠**: 使う人中心の設計（調べる→作る→確かめる→また調べる）、観察が近道（David Lightbown、本人）／1 週間で手間を 1 つ直せば 20 人の作業が毎日 1 時間速くなる計算（Robin-Yann Storm、本人）／約 2 年試し、うまくいかなかった案は戻した（Figma、本人）

## 3. 使いにくくなる原因 [ANTI]

| 原因 | なぜ使いにくいか | 直し方 |
|---|---|---|
| 全部の項目が最初から見えている | 大事な物が埋もれ、決めるのに時間がかかる | T2 |
| データの形のまま並べている | 考えと並びが合わず探し回る | T1 |
| よく触る物が折りたたみの中 | 毎回開く手間 | T2 |
| 奥が 3 段以上 | どこにいるか分からなくなる | T2 |
| 枠の中に枠、スクロールの中にスクロール | 線を読む力を使い、ホイールがどちらに効くか迷う | T9 |
| アイコンだけ、マウスを乗せないと分からない | 試さないと意味が分からない | T6 |
| 勝手に消える・動く UI | どこにあるか分からず不安 | T8 |
| 変えた所が分からない | 何を触ったか確かめるのに全部見直す | T4 |
| 「適用」を押すまで結果が見えない | 試す回数が減る | T3 |
| 毎回は触らない物が上の大きな場所を取る | 主役（作業する項目・プレビュー）が下に追いやられる | T8 |

## 4. スキル調整スタジオの診断（2026-11-09） [STUDIO]

`Assets/_Tools/SkillStudio/Editor/`（メニュー `Tools/スキル調整スタジオを開く`）。赤のスキルの「見た目」を開いた場合。

- **T2 守れていない（いちばん大きな原因）**: 開いた瞬間に、試し撃ち・保存の 2 枚、付け外しの 16 行、設定の欄のカード 12 枚が縦に並ぶ。最初に見える操作は 40 を超える。
- **T1 守れていない**: 欄の並びがプログラムの設定のまとまり（レーザーの色・模様、ビリビリ、発射口、派手さ…）の順そのまま。「稲妻を弱めたい」とき、付け外しの表・ビリビリの欄・派手さの欄のどこを触ればいいか分からない。
- **T9 守れていない**: カードの中にカード、その中にインスペクターの折りたたみ、さらに入れ子。
- **T4・T5 無い**: 変えた所が分からず、検索も無い（作る前の質問でユーザーが「初期値に戻す」と「検索」を選ばなかったので入れていない）。
- **T8 弱い**: 試し撃ちと保存のパネルがいつも上の大きな場所を取る。
- **守れている所**: T3（Play 中にすぐ反映）、T6（日本語の説明が画面下の帯に出る）、T7（ステージ背景スタジオと同じ骨組み）。
- **直すなら（案・未着手）**: 各ページの一番上を「よく触る項目」5〜8 個だけにし、残りは「詳しい設定」に 1 段だけしまう。やりたいことの名前（稲妻・光・強さ…）でまとめ直す。試し撃ちと A/B 切り替えは上の帯の小さなボタンに。変えた項目に印と「戻す」。直し方が何通りかあるので、作る前に見本ページで比べてもらう。

## 5. このプロジェクトのツールの決まり（案） [OURS]

2026-11-09 時点の案。ユーザーが採用を決めたら「案」を外す。

1. **最初の画面は「よく触る物」だけ**: 1 ページ・1 まとまりで最初に見える操作は 8 個くらいまで。残りは「詳しい設定」に 1 段だけ。奥は 2 段まで。
2. **まとまりは、やりたいことの名前で**: クラスの区切りではなく目的（光の強さを変える、当たり判定を広げる）でまとめる。1 つの目的の値が散らばらないように。設定ファイル側でまとめ直せないときは、ツールの画面側で「よく触る項目」の一覧（Niagara の Summary View のような物）を持つ。
3. **その場で見える**: 値を変えたら Play 中・シーンビューですぐ結果が見える。見えない値には小さな見本を付ける。
4. **変えた所に印、初期値に戻せる**: 初期値から変えた項目は名前の色を変え、横に「戻す」。
5. **項目が 20 を超える画面には検索**。
6. **枠は 1 重まで、中にスクロールを作らない**: StudioKit のカードの中にカードを入れない。まとまりは余白と見出しで。タブは 4 つまで。
7. **ラベルは言葉、説明は短く**: アイコンだけのボタンを作らない。説明は StudioKit の画面下の帯に 2〜3 行。スイッチの名前に「有効にする」を付けない。
8. **作る前に作業を聞き、作った後に使ってもらう**: 「どの順番で何を触るか」を先に聞き（[[fortress-designer-tool-style]] の「先に質問」と同じ）、作った後は使ってもらい、手が止まった所を直す。
