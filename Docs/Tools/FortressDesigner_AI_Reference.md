> Cold-start brief for Claude Code. Verified against source on **2026-10-03** (commit 8716908 + working tree); laser/destructible effect slots updated **2026-10-04**.
> Human guide: `Docs/Tools/FortressDesigner_ガイド.html`. **If you change anything under `Assets/_Game/Fortress/`, update both files in the same task** (see `CLAUDE.md`, `Docs/Tools/DOCS_GUIDE.md`).
> Japanese strings in backticks are exact UI labels.

## 0. Mental model
- Game: 「握れ、灼ける前に」 — 4 players (fixed), each owns one auto-rotating laser turret around a central core crystal; grip strength → laser thickness & heat; overheat → silence. Thousands of enemies (Swarm) path around obstacles to the core.
- **Fortress Designer** = one EditorWindow (`Tools/要塞/要塞デザイナーを開く`) with 9 tabs that **only edit runtime components in the open scene and ScriptableObject assets**. No private save format. Scene edits need scene save; SO edits persist even when made in Play Mode.
- Code: Runtime asmdef `MS2026.Fortress.Runtime` (ns `MS2026.Fortress`), Editor asmdef `MS2026.Fortress.Editor` (ns `MS2026.Fortress.EditorTools`), tests `MS2026.Fortress.Tests.EditMode` (Billboard, CameraRigLogic, CameraViewMath).
- Runtime refs: `MS2026.GripInputBridge.Runtime`, `DDrive.Runtime`, `DDrive.Generated`, `DDrive.Foundation`, `Unity.Netcode.Runtime`, `Unity.Burst`, `Unity.Mathematics`, `Unity.Collections`, `Unity.InputSystem`.

## 2. Window architecture (follow when extending)
- `FortressDesignerWindow` (UI Toolkit root, min 620×520). `enum Tab { GettingStarted, Turrets, EnemyWaves, Navigation, Destructibles, SmashBalls, Swarm, Camera, Test }`. Each tab = a `*TabView : VisualElement` with `Refresh()`; window calls `Refresh()` on the current tab every **150 ms** (`schedule.Every(150)`). Panels inside mostly use `IMGUIContainer` + `EditorGUILayout` (8 files) — thin TabView composing small Panel classes is the house style (user preference: "thin TabView + panels").
- Adding a tab: add enum value, `AddTabButton(bar, Tab.X, "ラベル", "tooltip")`, switch case in `SwitchTab` and `RefreshCurrentTab`, `internal void SwitchToXTab()`, a step in `GettingStartedTabView` (title/body/button), and update both docs.
- Field labels are Japanese via `(propertyPath, label)` tuple arrays + `PropertyField(new GUIContent(label, property.tooltip))` (Swarm panels, turret rotation/aim) or explicit `FloatField(new GUIContent("…","…"))`. Tooltips come from `[Tooltip]` on runtime fields → keep runtime tooltips Japanese and planner-readable.
- Edits use `Undo`/`SerializedObject`; scene-object edits done in Play Mode revert on exit (Unity behaviour) — tabs that place objects disable placement during Play.

## 4. Runtime systems (what the data means)
### Laser (`Runtime/Laser`)
- `LaserTurret` (`[DefaultExecutionOrder(-10)]`): fields `playerIndex` (0-3), `tuning` (`LaserTuningConfig`), rotation per-turret flags. State `TurretState { Idle, Charging, Firing, Overheated }`, `event OnStateChanged`, `Heat`, `HeatRatio01`, `CurrentThickness01`, `CurrentThicknessMeters`, `ChargeProgress01`, `IsFiring`. Direction = `transform.up`.
- Per frame: reads `GripInputBridge.Provider.IsGripping(playerIndex)` and `GetGripValue`. Not gripping → heat cools by `heatCoolingPerSecond`, Idle. Gripping → optional charge (`grip >= chargeGripThreshold01` for `chargeToFireSeconds`, once per grip) → Firing: `Heat += grip² × heatGainPerSecond × dt`; thickness01 = `gripToThicknessCurve(grip)`, meters = `Lerp(minThickness, maxThickness, thickness01)`; `Heat >= overheatThreshold` → Overheated for `overheatSilenceDuration` (cools meanwhile). Rotation speed × `firingRotationMultiplierCurve(thickness01)` / charging / overheated multipliers, smoothed by `rotationResponse`.
- Net hooks on `LaserTurret`: `GripSourceOverride` (`ITurretGripSource`; null = read `GripInputBridge.Provider` directly), `IsReplica` + `BeginReplica()/EndReplica()/ApplySnapshot(in TurretSnapshot)` (client shows host state; extrapolates rotation with `SignedRotationSpeed` and eases toward the received angle; `OnStateChanged` still fires so SE/feedback work on every PC), `CaptureSnapshot()` (host). `TurretSnapshot` = memcpy struct {State, Heat, Thickness01, ThicknessMeters, ChargeProgress01, AngleDegrees, SignedRotationSpeed}.
- `LaserBeamVisual` (LineRenderer; swappable; raycast end point is always drawn, but obstacle damage + `SwarmSystem.QueueBeam` only when `FortressNet.HasSimulationAuthority` (or swarm `IsReplica`); passes `owner = playerIndex` to `QueueBeam`; exposes `HasImpact` / `ImpactPoint` (z = muzzle z) / `ImpactNormal` for the frame — true only when the 2D raycast hits a non-trigger collider, never at the range end), `TurretAimIndicator` (aim line while not firing).
- `LaserTurretEffects` (added automatically in `LaserTurret.Awake` if missing — no scene edit needed; no serialized fields): plays `tuning.effects` (see §Effects). Muzzle: on `OnStateChanged(Firing)` → `StartFollowing(attach = turret.muzzle ?? transform)` + SE once; any other state → Stop. Impact: in `LateUpdate` (after `LaserBeamVisual.Update`) while `IsFiring && HasImpact` → follows a runtime helper `[LaserImpact] Pn` (HideFlags.DontSave) placed at `ImpactPoint`, up = `ImpactNormal`; SE once when contact starts; Stop when contact ends. Swarm hits: subscribes `SwarmSystem.Current.BeamHitsReported` **only while `effects.swarmHit` is non-empty**; each hit with `owner == playerIndex` → `PlayOnce` at the hit position (z = muzzle z), up toward the turret. Replicas get the same state changes and raycast locally, so every PC shows the effects with no network traffic. (The old `LaserTurretAudio` was deleted 2026-10-04 — it was never attached in any scene, so the firing SE never played before.) Swarm damage via `SwarmSystem.QueueBeam(origin,end,halfWidth,dps,maxHits)`; obstacles via `ILaserTarget`/`IAttributedLaserTarget` × `obstacleDamageMultiplier`.

| minThickness / maxThickness | 0.05 / 0.6 | world units |
| heatGainPerSecond / heatCoolingPerSecond | 1 / 0.6 | heat integral |
| overheatThreshold / overheatSilenceDuration | 10 / 3 | full grip ≈ 10 s to overheat |
| rotationSpeedDegPerSec | 45 | |
| firingRotationMultiplierCurve | (0,1)→(1,0.2) | slows with strength |
| chargingRotationMultiplier / overheatedRotationMultiplier / rotationResponse | 1 / 1 / 8 | |
| showAimIndicator / aimIndicatorLength / Width / Alpha | true / 6 / 0.06 / 0.35 | |
| range / maxDamagePerSecond | 20 / 20 | dps scales with thickness01 |

### Spawning & enemies
- `EnemyWaveConfig` (CreateAssetMenu `Fortress/Enemy Wave Config`): `waveName`, `spawnEntries: List<EnemySpawnEntry{ triggerTime, spawnPointId ([SpawnPointId] dropdown), enemyType, count=1, intervalBetweenSpawns=0.3 }>`, `loop`, `loopInterval=5`. Order irrelevant (sorted by triggerTime).
- `EnemySpawnDirector`: `wave`, `autoStartOnPlay=true`, `IsPlaying`, `ElapsedTime`, `StartWave()`, `StopWave()`, `RefreshSpawnPoints()` (collects child `EnemySpawnPoint`s if unset).
- `EnemyTypeDefinition` (`Fortress/Enemy Type Definition`): `displayName`, `simulationMode {Swarm, Actor}`, `maxHealth=10`, `moveSpeed=2`, `damageToCore=1`, `navigationProfile`, `turnSharpness` (Actor), `swarm{ radius=0.22, mass=1, acceleration=8, speedVariance=0.15, spriteSize=0.7, spriteSheet, frameCount=10, directionCount=8 (1/2/4/8), animationFps=12 }`, `visualPrefab` (Actor), `placeholderColor`. Sprite sheet layout: columns = frames L→R, rows = directions top→bottom **right, up-right, up, up-left, left, down-left, down, down-right**; empty → generated placeholder (`SwarmPlaceholderSheet`).
- `EnemyController` = Actor-mode minimal enemy (GameObject, `ILaserTarget`). Static registry `Active` + `Registered/Unregistered` events (OnEnable/OnDisable; fired before the spawner sets `definition`!), `RemovalReason {Removed, Died, ReachedCore}`, `Velocity` (valid on clients too — use it for facing/animation). Replica mode: `BeginReplica()`, `ApplyReplicatedState(pos, vel, snap)` (extrapolates with velocity, eases sharpness 10, snaps >3 units), `ApplyReplicatedRemoval(reason)` (fires `OnDeath` for Died, then Destroy); `TakeDamage` ignored on replicas. Creation goes through `EnemyActorFactory.Create(type, pos, fallbackPrefab)` (visualPrefab or fallback or empty GameObject + EnemyController). Note: no Actor-mode type exists in the project yet (`Default_EnemyType` = Swarm). `NavigationProfile` (`Fortress/Navigation Profile`) per enemy type (inflate cells for big enemies).
### Swarm (`Runtime/Swarm`)
- `SwarmSystem` (`[DefaultExecutionOrder(100)]`): SoA storage + Jobs/Burst (steer → spatial hash → PBD separation → finalize → compact) + GPU instancing (1 draw per enemy type, `SwarmSprite` shader, y-sort). Async: schedules at end of Update, completes next Update. API: `Spawn(def,pos)`, `SpawnBurst(def,center,radius,count)`, `ClearAll()`, `QueueBeam(...)`, `RegisterType(def)`, `ClearSpikes()`. No per-enemy GameObjects → **ShaderFX/EffectTarget cannot target swarm enemies; SpriteAnim not used for them**.
- `SwarmSettings` (`Presets/Default_SwarmSettings`): maxEnemies=40000 (re-Play to apply), maxFrameDelta=0.033, densityRadius=0.6, densityReferenceCount=6, densitySlowdown=0.55, minSpeedFactor=0.2, momentumTransfer=0.6, turnSharpness=10, separationIterations=3, separationStiffness=0.85, personalSpace=1, maxCorrectionRatio=0.6, wallStiffness=1, maxNeighborsChecked=48, obstacleAwareness=0.1, wallContactRange=0.6, wallSlide=0.9, arrivalMode=VanishAndDamage (or LingerAndAttack), arrivalRadius=0.6, lingerDamagePerSecond=1, spawnJitter=0.3, maxSpawnsPerFrame=3000 (host/offline spawns beyond this are carried to the next frame; 0 = unlimited; client replica spawns are never throttled), ySort=true, renderQueue=2990, hitFlashDuration=0.1, hitEffectsPerSecond=60 (header 演出; label `レーザー命中エフェクトの上限（個/秒・全員合計、0=無制限）`; 0 = unlimited but still ≤ `SwarmLimits.MaxHitReportsPerFrame` = 256 per frame), fallbackAreaSize=64. `SwarmPreset` enum drives the 4 presets. UI labels in `SwarmSettingsPanel` tuple list.
- `SwarmStressSpawner`, `SwarmHud` (on-screen stats, works in builds; positioned by `DebugOverlayLayout`; adds traffic KB/s, host send backlog, client 'Hostとのズレ' avg/max or full-state progress while networked; `SwarmStats` gained `replicaCorrections/replicaErrorSum/replicaErrorMax/replicaSnaps/pendingSpawns`), `SwarmSpike` records (inside vs outside swarm cost).
- Network side of `SwarmSystem` lives in the partial `SwarmSystem.Net.cs`. Every agent has `Storage.netId` (0–65535, carried through compaction; `SwarmIdPool` (pure, tested) hands ids out FIFO so a freed id is reused as late as possible) and `Storage.correction`. Host/offline: ids assigned in `ApplyPendingCommands`; events `AgentsSpawned(IReadOnlyList<SpawnRecord{Id,Type,Position,SpeedScale,AnimStart,Facing}>)` after applying spawns, `AgentsRemoved(IReadOnlyList<RemovalRecord{Id, EnemyRemovalReason}>)` after compaction (the scan job writes removed ids/reasons, count in `counters[3]`) and on `ClearAll`; `StorageReadable` fires once per frame right before scheduling — the ONLY safe moment to read `Storage` from outside. Client (`IsReplica`, `BeginReplica()/EndReplica()` both clear everything): `Spawn` returns false, `SpawnReplica(id, def, pos, speedScale, animStart, facing)`, `RemoveReplica(id, reason)` (removed in the next compaction via a `NativeHashSet`), `QueueCorrection(id, pos)` → `SwarmCorrectionJob` (first job in the chain) stores the error (target + vel×lead − pos) and adds `1−exp(−sharpness·dt)` of it per frame, snapping beyond `snapDistance`; replicas never die/vanish on their own (Linger mode still lingers), `ApplyCoreDamage` is skipped and beams are forced to 0 dps (hit flash only). `ConfigureReplicaCorrection(sharpness, snapDistance, leadSeconds)`.
- Beam hit reports (`SwarmSystem.Hits.cs`, 2026-10-04): `SwarmBeam.owner` (player index, −1 unknown; `QueueBeam(..., int owner = -1)`). `SwarmLaserJob` records `SwarmBeamHit { float2 position; int owner; }` when a beam touches an agent whose `flash <= 0` (not hit for ≥ `hitFlashDuration`), up to `maxNewHits` per frame; two beams on one agent in a frame report once; beams are visited starting at `beamOffset` (incremented every frame) so one turret can't monopolise the budget. Budget = `HitEffectBudget` (pure, tested token bucket: capacity = 1 s worth, refilled with `Time.deltaTime`, `PerSecond` = `SwarmSettings.hitEffectsPerSecond`). Recording only happens while `BeamHitsReported` has subscribers. After job completion (`CompleteSimulation` → `CollectBeamHits`) the main thread raises `event Action<IReadOnlyList<SwarmBeamHit>> BeamHitsReported` (the list is reused next frame). Works on replicas too (0-dps beams still flash).
### Navigation
- `NavigationField` (`IEnemyNavigator`): grid over bounds, 8-dir Dijkstra flow field to core(s) (`FlowFieldSolver`), auto-recompute on obstacle break/regen/move; `EnemyNavigation.Current` global. `NavigationObstacle` writes its Collider2D area as blocked / cost zone (`NavigationObstacleMode`). Map is XY plane (z=0), camera looks down +Z.
### Obstacles / Destructibles
- `DestructibleObstacle` holds only state (durability, destroyed, regen, invulnerable) and events: `Damaged(obs, amount, DamageSource)`, `HealthChanged`, `StageChanged(obs, stage)`, `Destroyed`, `Regenerated`, `SettingsChanged`, `InvulnerabilityChanged`. RequireComponent: `NavigationObstacle`, `DestructibleCollision`, `DestructibleVisual`, `DestructibleFeedback`, `DestructibleDropper`, `DestructibleLinker`, `DestructibleHealthBar` (old objects get them via migration, `DestructibleMigration`); sibling comps subscribe: `DestructibleCollision` (collider + nav; rubble → cost zone), `DestructibleVisual` (prefab per state, damage stages, fit to scale), `DestructibleFeedback` (`FortressEffect` per event via `FortressEffectPlayer.PlayOnce` at the obstacle position; tint player = `LastAttacker` for hit/stage, `DestroyedBy` for destroy, none for regen; placeholder debris when `onDestroyed` has no VFX), `DestructibleHealthBar`, `DestructibleDropper`, `DestructibleLinker` (groups / chain / protection; `DamageSource.Linked` not re-propagated).
- `DestructibleSettings` (type-level; saved in `DestructiblePreset`, `Fortress/Destructible Preset`) = durability + visual + feedback + drop + collision. `DestructibleFeedbackSettings` = `FortressEffect onHit` (+`hitInterval=0.15`), `onStageChanged`, `onDestroyed`, `onRegenerated`, `placeholderDebris/debrisCount/debrisColor` (the old Prefab+AudioClip `DestructibleEffect`, `DestructibleEffectPlayer` and `effectLifetimeSeconds` were removed 2026-10-04; no data had been assigned). Per-instance (not in preset): links, protection, position, size (= Transform scale).
- Attribution: `DestructibleAttacker { PlayerIndex, Turret }`.
- Replica mode (network clients): `IsReplica`, `BeginReplica()/EndReplica()`. While replica, the public mutators `ApplyDamage/DestroyNow/Regenerate/SetInvulnerable/Unlock` and `Update` (regen timer, self-repair) do nothing (only `_regenTimer` advances for `RegenProgress01` display). State changes arrive through `ApplyReplicatedDamage(health, amount, source, attacker)`, `ApplyReplicatedHealth`, `ApplyReplicatedDestroy`, `ApplyReplicatedRegenerate`, `ApplyReplicatedInvulnerable`, `ApplyReplicatedSnapshot(...)` (join-time; fires Destroyed/Regenerated when the destroyed flag differs, so a destroy effect may play once on join). These fire the same events, so Visual/Collision/Feedback/HealthBar/Dropper/Linker/SmashBall need no network code. Linker chains are automatically host-only (their `ApplyDamage/DestroyNow/Unlock` calls are no-ops on replicas). Drops stay local/cosmetic (user decision 2026-10-03: drop items are undecided; if they become pickups, spawn them host-side as NetworkObjects).
### SmashBall
- SmashBall + network: on replicas `SmashBallModule` skips rotation (`ActivateNext`/`Reconsider`) and the regen grace invulnerability (host sends Active/Invulnerable events instead); `AnyBroken`/history still fire on every PC with the replicated `DestroyedBy`. `SmashBallFloater` on replicas does not wander: `ApplyReplicatedPosition(Vector2)` targets (incl. bob), eased with sharpness 12, snaps when >3 units away, after `OnEnable`, or after Regenerated; `IsFloating` tells the host which positions to send.
- `SmashBallModule` (RequireComponent `DestructibleObstacle`, `SmashBallFloater`): `SmashBallSettings{ label, floating (SmashBallFloatSettings), onBroken (FortressEffect; tint = DestroyedBy), recordHistory=true, regenGraceInvulnerableSeconds=1, exclusiveRotation, rotationGroupId, rotationDelaySeconds=3 }`. Events: instance `Broken`, static `AnyBroken` (`SmashBallBreakInfo{ Module, Obstacle, Attacker, WorldPosition, Time }`). **Only records/notifies — gameplay effect of breaking is not implemented**; subscribe to `AnyBroken`. `SmashBallHistory` keeps last N, reset on Play. `SmashBallRotationGroup` = one active per group. Floating balls are not nav walls. Floating also has `returnToScreen=true`, `maxSecondsOffScreen=1`, `screenMargin=1`, `returnSpeedMultiplier=1.5`: `SmashBallFloater.TryGetScreenArea(rig, out Rect)` = `CameraViewArea.SharedPlayerRect(rig.preset, rig.guides.ReferenceAspect)` (intersection of the 4 player views; roll → inner square; no overlap → overview) inset by margin and intersected with the wander bounds (nav field is 68×68 vs ~50×28 visible, which is why balls used to vanish). Off-screen longer than the limit → steer (turn ×3, speed ×multiplier) to a random point in the central half; ends on entering it. Regenerate picks a random free spot (12 tries, `Physics2D.OverlapCircle` ignoring self/triggers) inside that area. Avoidance pushes out instead of stopping when already overlapping (used to freeze balls spawned inside walls). Scene overlay draws the screen area in cyan. `CameraViewArea` (pure, tested in `CameraViewAreaTests`).
### Effects (`Runtime/Effects`) — project-wide effect slots (user decision 2026-10-04: every effect slot uses D-Drive IDs)
- `FortressEffect` [Serializable]: `AssetId<VfxMarker> vfx`, `AssetId<SeMarker> se`, `bool tintWithPlayerColor = true`, `string colorParam = "Color"`; `HasVfx/HasSe/IsEmpty`. Used by `LaserEffectSettings`, `DestructibleFeedbackSettings`, `SmashBallSettings.onBroken`. **New effect slots anywhere in the game should use this type.**
- `FortressEffectPlayer` (static, D-Drive facades only): `PlayOnce(effect, pos, rot, player = -1)`, `SpawnVfx(...) → Handle<VfxMarker>`, `PlaySound(effect, pos)` (`Audio.PlaySe(se, pos)`), `StartFollowing(effect, Transform follow, player) → Handle` (spawn at the follow pose + `Vfx.Attach`; rotation keeps following only if the VFX's Anchor has FollowRotation), `Stop(ref handle)` (checks `Vfx.IsPlaying` first to avoid dead-handle warnings), `RotationFacing(Vector2 up)` (XY plane: transform.up = up). Tint = `Vfx.SetParam(h, colorParam, FortressColors.PlayerColor(player))` — silent no-op if the VfxData has no Param with that label.
- Lifetime / pooling / volume / spam control live in D-Drive data: VFX `LifeMode` (Loop for muzzle/impact, OneShot/Duration for one-shot slots — a Loop VFX in a one-shot slot never stops), SE `MaxConcurrent`/`CooldownSec`. D-Drive always rents VFX from its pool. **VFX `Flags.Net` must stay `Local`** (every PC triggers effects itself; Cosmetic would duplicate). D-Drive has no API to scale a live VFX, so effects cannot follow laser thickness.
- Editor: `Editor/Effects/FortressEffectDrawer` (`[CustomPropertyDrawer(typeof(FortressEffect))]`: foldout header with summary `エフェクト✓ 効果音✓` / `（未設定）`; fields `エフェクト(VFX)`, `効果音(SE)` (D-Drive `AssetIdDrawer` pickers), `プレイヤー色で色付け`, `色を入れる項目名`; buttons `Asset Browser`, `VFX Editor`, `▶ 試す` (Play only)). Applies automatically wherever a `FortressEffect` is drawn with PropertyField (destructible / smash-ball drawers, inspectors). `FortressEffectPreview`: `PreferredPlayer` (set by the turret tab), `CanPlay` (Play && Vfx/Audio bound), `Play(property)` resolves the pose: `LaserTuningConfig` target → a turret using it (prefers PreferredPlayer) at its muzzle, non-muzzle slots 4 units ahead facing the turret; Component target → its position; otherwise the game camera / SceneView center at z=0. ### Camera

- **Swarm replication = snapshot mode (2026-10-05, user decision; default)**. Why: in correction mode the client mixes its own simulated positions with host positions agent-by-agent at different times; in a packed crowd the mean error (~0.4) is about one agent spacing, so a corrected agent overlaps uncorrected neighbours and PBD separation throws both → the whole crowd shakes and opens gaps (user report with screenshot). `SwarmNetworkHub.replicationMode` (`SwarmReplicationMode { Snapshot (default), Corrections }`; Corrections = everything below, kept for comparison; the hub is now `partial`, snapshot code in `SwarmNetworkHub.Snapshot.cs`). Message (`FortressNetChannel.SwarmSnapshot=4`, `ReliableFragmentedSequenced`, identical bytes to every synced client): `uint serial, double hostTime, float hostDelta, int ratioQ, byte kx, byte ky, int continuing, uint checksum, NativeArray despawns, spawns, bits`. Join/resync: `RequestFullStateRpc` → after the next encode `SwarmSnapshotKeyframeJob` builds `SwarmKeyframeEntry {SwarmNetEvent Spawn (h1), short X2,Y2 (h2)}` for all → `SwarmKeyframe=5` (`serial, hostTime, hostDelta, layoutHash, checksum, entries`) unicast, then the client joins `_snapshotClients` (same reliable pipeline ⇒ later deltas arrive after it). No remote clients → stream reset (next snapshot = everyone spawns). **Client**: `SnapshotDecoder` (per-netId `Alive`, `H1/H2`, outputs `SnapPos/SnapVel` floats); `SwarmSnapshotDecodeJob` / `SwarmSnapshotKeyframeApplyJob` run with `.Run()` on the `Allocator.Temp` arrays read from the message; serial gap, continuing-count or checksum mismatch → `RequestSnapshotResync` (counted in `NetTrafficStats.SwarmSnapshotResyncs`, must stay 0). Error stats in this mode = extrapolation miss measured when a new snapshot arrives (all agents, flagged audit so `errAudit == errAvg`). ## 6. Gotchas
1. Scene-object changes during Play revert; SO (Presets) changes during Play persist — warn users before experimenting in Play.
2. All 4 turrets share `Default_LaserTuningConfig`; editing it affects everyone.
3. Spawn point ring generator **replaces** existing spawn points.
4. Swarm capacity (`maxEnemies`) needs re-Play.
5. Destructible size = Transform scale; visuals/colliders follow. Preset excludes per-instance link/protection settings.
6. SmashBall break has no gameplay effect yet (by design hook `AnyBroken`).
7. ShaderFX on a sprite disables billboard for that sprite; swarm enemies can't use ShaderFX.
8. Camera tab setup buttons are disabled during Play.
9. Tab refresh is polling (150 ms) — expensive panels should early-out.
10. Multiplayer is mid-migration (plan `C:\Users\soret\.claude\plans\snoopy-forging-castle.md`): Phase 0 (connect), 1 (turrets), 2 (destructibles + smash balls), 3 (actor enemies) and 4 (swarm) done; core HP / win-lose / rounds (Phase 5) and host migration (Phase 6) remain — core HP is still applied only on the host (clients' core HP doesn't move). On clients the designer's destructible/smash-ball Play test buttons do nothing (replicas) — use them on the host. Editor asmdef refs `Unity.Netcode.Runtime`; runtime refs `UnityEngine.UI`. Effect slots: VFX must be registered in D-Drive (drop the prefab in `Assets/_Game/DDrive/SourceAssets/Vfx/<Category>/`), keep `Flags.Net = Local`, use Loop LifeMode for muzzle/impact — and then set `Flags.Pool.Kind = Pooled` + `MaxCount` > 0 (8 recommended), otherwise D-Drive Validation warns "LifeMode=Loop ですが Pool 上限が未設定です".
