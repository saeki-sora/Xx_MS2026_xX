## 0. Mental model
- uGUI based. One **`UiRoot`** per scene (`[UI]`, `[ExecuteAlways]`, exec order −100) owns one Screen-Space-Overlay **Canvas per layer** (`[UI Layer] <id>` children, created by `EnsureLayers()` also in edit mode) from a **`UiLayerSettings`** asset (default layers Background 0 / HUD 100 / Menu 200 (oneAtATime) / Popup 300 / Toast 400 / Transition 900 / Debug 1000, reference resolution 1920×1080, match 0.5, safeArea 0.92).
- A **screen** = prefab (or scene object) whose root has **`UiScreen`** (+CanvasGroup). Screens are opened **by name** (`screenId`) through `UiRoot.Open/Close/Toggle/Back/SwitchTo/LoadScene`. Catalog prefabs (`UiScreenCatalog`) are instantiated on first open under their layer canvas; scene-placed screens under `[UI]` are registered automatically.
- **D-Drive is used as parts** (user decision 2026-10-06): element/screen motions are D-Drive `UiFx` presets (`UiPresetRef`, 59 presets) or `UiTweenId`s; sounds are `SeId`s; screen-transition curtains and the screen/layer manager are our own. We do **not** use D-Drive `Ui.Open`/`CanvasData`.
- **Game → UI data** goes through the static blackboard **`UiValues`** (string key → `UiValue` number/bool/text/color, change-only notifications, no alloc for numbers). `FortressUiValues` (on `[UI]`) writes the game state every LateUpdate; binding components read keys. Keys are documented in a **`UiValueCatalog`** asset (label, description, kind, category, range, sample values). In edit mode the studio can publish **sample values** so bindings show without Play.

## 2. Runtime API
- `UiRoot`: fields `layerSettings`, `catalog`, `keepAcrossScenes=true` (DontDestroyOnLoad; a second `UiRoot` from a later scene destroys itself), `backWithEscape=true` (Esc / gamepad East → `Back()`, ignored while a curtain plays). Static `Active`. `Open(id, onShown)` (unknown id → warning, false; already-open & visible → just bring to front), `Close(id, onHidden)`, `Toggle`, `IsOpen`, `Back()` (closes the front-most screen with `closeOnBack`), `CloseLayer(layerId)`, `SwitchTo(id, transition, onDone, closeScreenId)` (cover → close same-layer screens + `closeScreenId` instantly → show target instantly → reveal), `LoadScene(scene, transition, onDone)` (cover → hide all, `LoadSceneAsync` → reveal when done), `PlayTransition(transition, onCovered, isReady, onDone)`, `Get(id)` (**instantiates** a catalog screen if needed), `GetIfCreated(id)` (only already registered/instantiated, never creates), `OriginScenePath` (Play only: `gameObject.scene.path` captured in the first OnEnable, i.e. before `DontDestroyOnLoad`), `EnsureLayers()`, `LayerCanvas(id)`, `LayerOf(screen)`, events `ScreenOpened/ScreenClosed(string)`, `OpenScreens`. `Start` (Play): ensures an `EventSystem` + `InputSystemUIInputModule` if none, registers scene screens, opens `openOnStart` screens and hides the rest.
- `UiScreenStack` (pure): `Push(id, layer, layerOrder, oneAtATime, closesOnBack) → ids to close`, `Remove`, `IsOpen`, `TopForBack()`; order = layer sortOrder then open order.
- `UiScreen`: `screenId`, `displayName`, `layer` (`[UiLayerId]`), `memo`, `openOnStart`, `closeOnBack=true`, `modal` (runtime child `[Modal Blocker]` full-screen Image, DontSave, color `modalDim`), `showMotion` (FadeIn 0.2) / `hideMotion` (FadeOut 0.15), `firstSelected`, `onShown/onHidden` (UnityEvent) + C# events `Shown/Hidden`. `Show(done)` / `Hide(done)` play the root motion **and** `UiElementMotion.Play(OnShow/OnHide)` on every *active* child, wait for all, then set interactable / deactivate. `SetVisibleImmediate(bool)`. **Since 2026-10-14 `PlayAll` skips children for which `UiBindVisible.IsHiddenByValue(child, screen)` is true** (the child or a parent up to the screen has an active `UiBindVisible` that is currently hidden) and does not wait for them; when such a binding later turns visible it plays `OnShow` on itself **and on every active `UiElementMotion` inside it** that is not under another hidden binding (`PlayShowInside`; before, only its own motion). Reason (user: result/game-over screens 「一瞬先にその画面が出てから、もう一度出直す」): the screen's OnShow fade/slide tweens write the same CanvasGroup alpha that `UiBindVisible` uses, so value-hidden parts (e.g. the result `Panel`, step > 1.5) faded in with the screen and then replayed when their step came. `State`, `IsVisible`, `Label`, `SourcePrefab` (runtime only, set by `UiRoot.Resolve` when it instantiates a catalog prefab; null for scene-placed screens).
- `UiButtonAction` (RequireComponent Button): `action` `OpenScreen/CloseScreen/CloseThisScreen/Back/SwitchScreen/LoadScene/PlayMotion`, `target` (screen id / scene name / motion name), `transition`, `motionTarget`. `SwitchScreen` passes the button's own screen as `closeScreenId`.
- `UiMotion` [Serializable]: `source` (Preset/Tween), `preset` (D-Drive `UiPresetRef`: Preset, Duration (0 = preset default), Distance, EaseOverride, Se), `tween` (`UiTweenId`), `delay`, `se`; `IsEmpty`, `FromPreset(preset, duration, delay)`, `Summary`.
- `IUiMotionPlayer` / `UiMotionPlayers.Current` (default = D-Drive `UiFx`; `CanPlay` = `UiFx.IsBound`; when not playable motions are skipped and treated as finished). `UiMotionPlayers.Override` for tools.
- `UiElementMotion` (pointer/select/submit handlers): `entries` (`trigger`, `name`, `valueKey` (`[UiValueKey]`), `target`, `motion`). Triggers `OnShow, OnHide, OnClick (click+submit), OnHover (enter+select), OnPress, OnValueUp, OnValueDown (subscribes UiValues; **since 2026-10-13 a value trigger that fires again while the same entry is still playing stops it (`Stop(complete: true)`) and restores the target's rest pose (localScale / localEulerAngles / anchoredPosition captured when no value motion was running on that target) before restarting** — otherwise fast-changing values (kill counts) made punch/jelly start from the already-inflated scale and the element grew without limit; done in `RestartValueMotion`), Loop (started by OnShow / OnEnable outside screens, stopped on hide/disable), Manual (PlayNamed)`. `Play(trigger, onComplete)`, `PlayNamed`, `Has`, `IsBusy`. Delays use unscaled time.
- `UiScreenTransition` asset (`Create › UI › Screen Transition`): `displayName`, `pattern` (Fade=0, Wipe, Iris, Blinds, Diamonds, RuleTexture, Burn), `color`, `coverSeconds 0.35`, `holdSeconds 0.05`, `revealSeconds 0.35`, `ease`, `angle`, `revealPassThrough=true` (reveal continues in the same direction; implemented by +180° / inverted rule order while revealing), `count 8`, `softness 0.06`, `center`, `ruleTexture`, `invert`, `edgeColor` (HDR), `edgeWidth 0.08`, `seCover`, `seReveal`; `ApplyTo(material, progress, revealing, aspect)`; `CreateDefault()` (fade).
- `UiTransitionTimeline` (pure): Covering → Holding (until hold elapsed **and** ready) → Revealing; `Tick(dt, ready) → (coveredNow, finishedNow)`.
- `UiTransitionOverlay` (RawImage on `[Transition Overlay]` under the Transition layer, created lazily): `Play(transition, onCovered, isReady, onDone)` (a new Play while one runs fires the previous callbacks first), blocks raycasts while visible, plays `seCover/seReveal` via D-Drive.
- `UiValues`: `Set(key, float|int|bool|string|Color|UiValue)` (no event when equal; numbers compared with 1e-5), `TryGet`, `GetNumber`, `GetBool`, `Subscribe(key, Action<UiValue>, invokeNow=true) → IDisposable`, `ClearValues()`, `Keys`, `Version`; entries reset on SubsystemRegistration.
- `UiValue`: `Kind (None/Number/Bool/Text/Color)`, `Number`, `Text`, `Color`, `AsBool`, `AsNumber`, `Format(format)` (string.Format, invariant culture; bad format returns the format string).
- **First-frame flash fix (2026-10-14)**: D-Drive `UiTweenManager.PlayData/PlayTracks` only registers a tween; the first values are written on the next `Tick`, so for one rendered frame a just-opened screen showed its finished rest pose (traced in Unity: Result root alpha 1.00 on the opening frame, 0.23 on the next). `UiMotionPlayers`' D-Drive player now calls `DDriveRuntimeBootstrap.Instance.UiTweens.Tick(0f)` right after every `UiFx.Play` (alias `DDriveBootstrap`), which applies the start state of all active tweens at their current elapsed time (dt 0 → nothing advances; tracks still inside their own `Delay` are untouched). D-Drive itself is unchanged.
- `UiBindInteractable` (RequireComponent Selectable): `condition` (same `UiVisibleCondition` as UiBindVisible), `threshold` → `Selectable.interactable` (e.g. `lobby.canStart`).
- Bindings (all `[ExecuteAlways]`, field `key`): `UiBindText` (`format "{0}"`, `countUpSeconds` (Play only), `whenEmpty`; target = TMP_Text or Text on the same GO), `UiBindFill` (`fill` Image (Filled → fillAmount, else anchorMax.x), `min/max`, `smoothSeconds 0.08`, optional `trail` Image with `trailDelay 0.4`, `trailSpeed 1.2`), `UiBindColor` (`target`, `gradient` yellow→orange→red, `min/max`, `keepAlpha`; color values used directly), `UiBindVisible` (RequireComponent CanvasGroup; `condition WhenOn/WhenOff/WhenGreater/WhenLess/WhenEqual`, `threshold`; runtime alpha 0 + no raycast, **edit mode alpha 0.25** (`EditorHiddenAlpha`) so hidden parts stay editable; plays the same GO's `UiElementMotion` OnShow/OnHide when toggling in Play).
- Game side: `FortressUiKeys` constants + `Describe()` (catalog rows): `local.player/playerLabel/color/heat/overheated/firing/charge/thickness/grip`, `player.N.heat/overheated/firing/grip/connected/color/kills` (N = 1..4), `other.K.player/label/color/heat/overheated/connected` (K = 1..3, the other players in ascending order, category `ほかの人`, 2026-10-17, §4f), `core.hp/hp01/destroyed`, `swarm.alive`, `kills.total/local/combo/comboTime01/milestone/milestoneShowing` (category `撃破`, 2026-10-13), `wave.time/playing`, `net.mode/players/lastError`, `lobby.status/selectedPlayer/selectedLabel/name/phase/isHost/inRoom/connecting/inGame/players/readyCount/allReady/canStart/countdown/countingDown/localReady/gripHold/address/hostAddress/foundHosts`, `player.N.name/ready/isHost/isLocal/ping/taken`, `message.title/body`, `toast.text` (all in `Describe()`; `UiStudioSetup.RegisterGameValues` also fills Japanese sample texts via `SampleText(key)`, replacing old "サンプル" samples). `FortressUiValues`: when `GameSession.Active` exists and NGO is listening, `player.N.connected` and `net.players` come from the session roster (correct on clients too). `FortressUiValues` (finds turrets/core/director/bootstrap every 1 s; local player = `FortressNetworkBootstrap.LocalPlayerIndex`, else camera viewer, else 0; `player.N.connected` is accurate on the host only, clients know only themselves; grip values for other players are only meaningful on the host). `LobbyScreenController` (`playerButtons[4]`, `hostButton`, `joinButton`, `leaveButton`, `addressField` (InputField or TMP_InputField, default 127.0.0.1), `nextScreenId="Hud"`, `transition`, `hideTemporaryConnectUi=true` (disables `FortressConnectUI` components → its OnGUI stops), `defaultPlayer`); `HostGame/JoinGame/StopGame` via `FortressNetworkBootstrap.Instance`; every Update while the lobby is enabled checks `NetworkManager` (connected client, or listening host) — including connections started by launch args / the test bats — and then once `SwitchTo(nextScreenId, transition, closeScreenId: own screen)`; failure is reported only after a button-started attempt; status text goes to `lobby.status`. `FortressConnectUI` components are disabled on lobby enable and stay disabled until the scene reloads. (`FortressLegacyUiSwitch` was deleted on 2026-10-17 together with `LocalTurretGaugeHud`, see §5.)

## 3. Transition shader
`MS2026/UI/ScreenTransition` (CG, UI blend, ZTest `unity_GUIZTestMode`): `_Progress` 0..1, `_Pattern`, `_Angle`, `_Count`, `_Softness`, `_Center`, `_RuleTex`, `_Invert`, `_EdgeColor`, `_EdgeWidth`, `_Aspect`, `_Color`. Each pattern computes a per-pixel cover order; Fade multiplies alpha by progress; Burn uses 2-octave value noise + distance and adds a glowing edge band.

## 4c. Keeping Play-mode edits (`Play中の変更`, 2026-10-12; user decisions: ask every time when Play stops; record UI edits made anywhere — Inspector, Scene view, studio)
- **Recorder** `UiPlayChangeRecorder` (`[InitializeOnLoad]`, works without the window): hooks `Undo.postprocessModifications`; only while `EditorApplication.isPlaying && Enabled` (EditorPrefs `MS2026.UiStudio.RecordPlayChanges`, default true). So only edits that go through Undo (Inspector, Scene handles, `SerializedObject.ApplyModifiedProperties`, `Undo.RecordObject`) are captured; values the game sets from code are not. `m_Name` changes are processed first so paths use pre-Play names (`UiPlayLocator.RememberOriginalName`). Objects with `HideFlags.DontSave` (e.g. `[Modal Blocker]`) are ignored. Keeps a static `LiveTargets` map (key → live object); on `ExitingPlayMode` it re-reads every recorded property (`UiPlayValueIo.TryRead`): values equal to the first `beforeValue`/`beforeObject` (undone with Ctrl+Z) and properties that no longer exist are dropped, the others get the final value. On `EnteredEditMode`, if anything was recorded this Play (SessionState `MS2026.UiStudio.PlayChangesRecorded`), `delayCall` → `DisplayDialogComplex("Play 中に変えた UI の値", …, "残す", "一覧で選ぶ", "捨てる")`; Esc/× = `一覧で選ぶ` (cancel slot, nothing lost) → opens the page; `残す` → `UiPlayChangeApplier.ApplyKept()` (+ page if rows remain); `捨てる` → clear. If nothing is applicable: `一覧を見る` / `捨てる`.
- **Address** `UiPlayTarget` (`UiPlayLocator.TryLocate`): object inside a screen with `SourcePrefab` → `Prefab` destination (asset path of the prefab, path from the prefab root); inside a scene screen → `Scene` destination (scene path = nearest `UiRoot.OriginScenePath`, else `scene.path`; `anchorId` = `screenId`); under a `UiRoot` but outside screens → `Scene`, anchor `""` (= the UiRoot). Anything else (not UI), persistent assets and preview-scene objects (prefab stage; those already save to the file) are not recorded. Path = list of (name, index among same-name siblings) from the anchor; component = AssemblyQualifiedName + index among exact-type components. A path step ending in `(Clone)` or an empty asset path sets `problem` (not applicable). Object-reference values: persistent → `objectValue`; object under the same anchor → `referencesLocal` + `reference` address; else `problem`.
- **Store** `UiPlayChangeStore` (`ScriptableSingleton`, survives domain reload, not saved to disk): `Items`, `Version`, `Count`, `ApplicableCount`, `Contains`, `Merge` (same `Key` = same object + component + propertyPath → one row: first `before`/order kept, value updated, user's `keep` kept), `Remove`, `RemoveAll`, `Clear`, `Touch`. Pure logic: `UiPlayChangeList` (`Merge`, `ApplyOrder` = `.Array.size` rows first, `GroupByDestination`), `UiPlayPath` (`IndexAmongSameName`, `FindPosition`, `Describe`), `UiPlayValueText` (`TryBool` "1"/"0"/true/false, `TryLong`, `TryDouble` (invariant, ±Infinity/NaN), `Same` (relative tolerance 1e-6), `Short`).
- **Applier** `UiPlayChangeApplier.Apply(changes)` / `ApplyKept()` (refused while playing): per destination. Prefab: if that prefab is open in the prefab stage, write there (Undo, mark dirty); else `LoadPrefabContents` → write → `SaveAsPrefabAsset` → `UnloadPrefabContents`. Scene: loaded → write with Undo + `MarkSceneDirty` (user saves); not loaded → `OpenScene(Additive)` → write → `SaveScene` → `CloseScene`. Scene anchor = first `UiRoot` (anchorId "") or `UiScreen` with that `screenId` in that scene. A missing component whose index == current count is added (`Undo.AddComponent` / `AddComponent`), which covers `UiElementMotion`/`CanvasGroup` added by the studio in Play. Each write uses `UiPlayValueIo.TryWrite` (Integer / Boolean / Float (double aware) / String / Enum / ArraySize / Character / LayerMask / ObjectReference) and applies immediately so array elements exist after a size change. One Undo group `Play中の変更を残す`. Applied rows are removed; failed rows stay with `problem` (shown as `残せません: …`). `Report` (`Applied`, `Failed`, `Destinations`, `Problems`, `Summary`, `Log()`).
- **Page** `UiPlayChangesPage` (icon ◉, badge = pending count, yellow): toggle `Play中の変更を記録する`, status note, `選んだ物を残す` (disabled in Play / when nothing applicable), `選んだ物を捨てる`, `全部選ぶ`, `全部外す`, `全部捨てる` (confirm), result line, `PlayChangeListPanel` (grouped by destination with `Prefab`/`シーン` chip; row = keep toggle, `where › component`, `label:  before → after`, problem line, `見る` (live object in Play, else the asset), `✕`), and a `残せる物・残せない物` note.
- Not kept (by design): structural changes (create/delete/reparent/reorder GameObjects, remove components), values on runtime-created objects, edits while recording is OFF. A domain reload during Play loses `LiveTargets` (final-value refresh is skipped for earlier rows; their last recorded value is used).

## 6. Gotchas
1. Not run inside Unity yet (see header). Verify: open the window, create root + templates, Play the Lobby → Host → HUD flow, try transitions.
2. Bindings run in edit mode and write to Text/Image/CanvasGroup, so sample values end up saved in prefabs; harmless because runtime overwrites them, but expect diffs in prefabs after previewing.
3. `UiBindFill` without a Filled image changes `anchorMax.x` assuming the full bar ends at anchor x=1.
4. Loop motions animate their own CanvasGroup alpha (Blink etc.); don't put a Loop alpha motion on the same object as `UiBindVisible` — use a child (the HUD template does).
5. Asset creation goes through `StudioAssets.UniquePath` because `AssetDatabase.GenerateUniqueAssetPath` returns "" when the parent folder does not exist (this crashed Stage Studio's `＋ 新しいステージ` on 2026-10-06 before the fix).
6. `LoadScene` with `keepAcrossScenes`: put `[UI]` only in the first scene; a later scene's own `[UI]` (and its screens) is destroyed. A second EventSystem in the new scene will warn.
7. TextMeshPro is supported by bindings, but the project contains **no Japanese font file**; templates use legacy Text. A planner must add a redistributable Japanese .ttf/.otf (e.g. an OFL font) and use the TMP panel; never ship OS fonts (Meiryo/Yu Gothic) without checking their licence.
8. D-Drive presets need `UiFx.IsBound` (bootstrap in scene) at runtime; without it motions are skipped and screens show/hide instantly.
9. Never name a MonoBehaviour helper after a Unity message (`Start`, `Update`, `Awake`, `OnEnable`…) with parameters: Unity logs "Script error (X): Start() can not take parameters." `UiElementMotion`'s internal "play this entry" method is therefore `Launch(entry, player)` (was `Start`, fixed 2026-10-07).
10. `UiStudioWindow` (like the Stage window) disposes its context only in `OnDestroy` and refreshes from `OnInspectorUpdate` (0.25 s throttle, immediate after `OnFocus`), not `rootVisualElement.schedule`, so the view never freezes after Play/layout changes.

10b. Play-mode edits are matched back by **names** (index among same-name siblings) from the screen root / UiRoot; renaming a part after Play (before applying) or reordering same-name siblings makes rows fail with `部品が見つかりません`. `UiPlayChangeStore` lives only until the editor closes.
10c. `UiRoot.Get(id)` instantiates catalog screens; editor code that only wants to *look* must use `GetIfCreated(id)`.

11. Session: `GameSession` opens screens one frame after Start (coroutine) so `UiRoot.Start` has run. Menu screens are `closeOnBack=false`; Esc is handled by the session (Browsing/Connecting → back to top; InGame → opens Pause **next frame**, because `UiRoot.Update` would otherwise close it as "Back" in the same frame). Pause/Message are `closeOnBack=true` and closed by UiRoot.
12. Session: never `!=`-compare cached scene objects across Play (see Stage gotcha 11b); `NetworkManager` always moves itself to DontDestroyOnLoad, so `GoToTitle` destroys it explicitly after shutdown (plus a DDOL D-Drive bootstrap / UiRoot if any), then loads Title single.
13. Session: MCP game-view screenshots during Play produced Unity "PlayerLoop internal function has been called recursively" warnings (and once dropped the MCP connection). They did not occur when the same flow ran without screenshots — not caused by game code.
14. "画面とロビーも作り直す" overwrites the session prefabs (same paths/GUIDs) and recreates `Lobby.unity`; hand edits are lost — use "足りない物だけ作る" after customising.
