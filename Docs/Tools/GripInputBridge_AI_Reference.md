## 0. Mental model
- Input layer between grip sensors (4 players, fixed: `GripInputBridgeConstants.PlayerCount = 4`) and the game. Game reads one normalized value 0–1 per player; source can be keyboard simulator, serial hardware, or a recorded log — hot-swappable at runtime.
- Pipeline per player, sampled **once per frame**: `transport.GetRawValue` (0–1) → `IGripSignalFilter.Filter` → `GripCalibrationProfile.Normalize` (dead zone → min–max → response curve) → `GripEdgeDetector.Update` (hysteresis) → cached values + `OnGripStarted/OnGripReleased`.
- Zero setup: `GripInputBridge.Provider` lazily creates a provider with the shared `GripInputBridge.Simulator` (one `SimulatedGripTransport` for the whole process); hidden `GripInputBridgeRuntimeDriver` (`[DefaultExecutionOrder(-1000)]`, `RuntimeInitializeOnLoadMethod(SubsystemRegistration)`, DontDestroyOnLoad, HideInHierarchy) calls `GripInputBridge.Tick()` every Update.

## 2. Public API
```csharp
namespace MS2026.GripInputBridge
static class GripInputBridge {
  IGripInputProvider Provider { get; }              // lazy: new GripInputProvider(Simulator)
  SimulatedGripTransport Simulator { get; }         // the ONE keyboard simulator; window presets + composite use it. Never `new SimulatedGripTransport()` for the game.
  IGripTransport CurrentTransport { get; }          // check before restoring: only undo your own SetTransport
  void SetTransport(IGripTransport t);              // throws on null; last caller wins (single global slot)
  void SetFilterSettings(GripFilterSettings s);     // rebuilds 4 filters + edge detectors (state reset)
  void SetCalibrationProfiles(GripCalibrationProfile[] p); // null entries → CreateDefault(i) (linear, deadZone 0.03)
  void StartRecording(string dir = null);           // restarts if already recording; default <project>/GripLogs
  void StopRecording();
  string CurrentRecordingFilePath { get; }  bool IsRecording { get; }
  internal void Tick();                              // driver only; records raw/filtered/normalized for 4 players when recording
}
interface IGripInputProvider {
  float GetGripValue(int p);   // final 0-1 (game uses this)
  float GetRawValue(int p);    // transport value before filter/calibration
  bool  IsGripping(int p);     // edge-detector state
  event Action<int> OnGripStarted, OnGripReleased;
  GripDeviceStatus GetStatus(int p);  // Connected / Disconnected only (Stale, Suspicious defined but unused)
}
// GripInputProvider also exposes Transport, GetFilteredValue(p), Update(), SetTransport/SetFilterSettings/SetCalibrationProfiles.
interface IGripTransport { bool IsConnected(int p); float GetRawValue(int p); event Action<int> OnConnected, OnDisconnected; }
```
- Invalid player index → 0 / false / Disconnected (no exceptions). Reads before first Update trigger one sample (`EnsureSampledAtLeastOnce`).
- Filters/edge detectors are stateful → never call `Filter`/`Update` more than once per sample (provider caches per frame for this reason).

## 3. Transports
| Transport | Construct | Behaviour |
|---|---|---|
| `SimulatedGripTransport` | `(Key[] keys = {Q,W,O,P}, rise = 3.0/s, decay = 1.5/s)` | Input System `Keyboard.current`; held → +rise·dt, released → −decay·dt, clamp 0–1; updates once per frame per player. `SetPreset(p, GripWaveformPreset)` overrides keys; `SetConnected(p, bool)` fakes disconnect. Presets: `None`, `Soft` (0.2–0.3 sine 0.5 Hz), `Firm` (0.5–0.6), `Full` (0.9–1.0), `RhythmTestPulse` (0.4 s beats: 0.8 / 0). |
| `SerialGripTransport` (define-gated, `IDisposable`) | `(GripDeviceConfig)` / `(GripDeviceConfig, bool logOpenError)` (false = no LogError when the port can't be opened; used by the port search) | Opens `SerialPort(name, baud)`, ReadTimeout 500, NewLine "\n"; background thread `ReadLoop` parses with `GripSerialProtocol.TryParseSamples`; values via `Volatile`. `IsConnected` = received at least once **and** last sample ≤ `heartbeatTimeoutMs` ago. `GetRawValue` = `config.ToGripRawValue(received)`; `GetReceivedValue` = pre-conversion (diagnostics). Open failure → `Debug.LogError`, transport inert, `IsPortOpen == false` (callers must check and not install it). `OnConnected` fires once per player on first sample (from background thread!). `OnDisconnected` never fired. **Must `Dispose()` when swapping** (frees COM port). Also `string PortName`, `bool HasReceivedData` (any valid sample ever parsed), `double SecondsSinceLastData` (+∞ if never), `bool IsPortLost`, `static string[] GetAvailablePortNames()` (`SerialPort.GetPortNames`, empty on error). **Read errors (2026-10-12)**: the first error of a streak logs one warning; after 5 consecutive non-timeout errors (~0.5 s) or when the port reports closed, `IsPortLost = true`, one warning `… が使えなくなりました（USBが抜けた など）`, and the read thread exits (it used to log every 100 ms forever). A successful line resets the streak. Reopening is the caller's job. **Diagnostics (2026-10-14)**: every line read (before parsing) is stored as `_lastLine` + `Interlocked` counters; parse failures also set `_lastRejectedLine` / `_linesRejected`. `GetDiagnostics()` → `GripSerialDiagnostics { LastLine, LastRejectedLine, LinesReceived, LinesRejected, SecondsSinceLastLine (+∞ if none) }`; `HasReceivedDataFor(p)` = that player ever parsed. |
| `SerialGripPortSearch` (define-gated, `IDisposable`, 2026-10-12) | `(GripDeviceConfig config, IReadOnlyList<string> ports, int timeoutMs, bool logFirstPortError)` — **main thread** (clones `config` per port with `Object.Instantiate`, sets `serialPortName`) | Opens every candidate concurrently via `Task.Run(new SerialGripTransport(copy, false))` so a slow port (Bluetooth COM) can't freeze the frame. `Poll()` (main thread, every frame): the first candidate in list order whose transport `IsPortOpen && HasReceivedData` wins; after `timeoutMs` the first candidate (configured port) wins if it opened (old behaviour: device may start sending later), else none. `IsDone`, `Result` (caller owns/Disposes), `ResultHasData`, `DescribePorts()`. All other candidates are disposed (`ContinueWith`, also ones still opening) and their config copies `Object.Destroy`ed. `Dispose()` before done = abandon all. |
| `CompositeGripTransport` | `(IGripTransport device, IGripTransport fallback, int devicePlayerCount = 4)` | **2026-10-20**: `DevicePlayerCount` (clamped 0–4) — only players `p < DevicePlayerCount` (`UsesDevice(p)`) ever look at the device; later players are fallback-only even if the device sends values for them (device events for them are not forwarded). Per player: `IsDeviceConnected(p)` (= `UsesDevice(p) && device.IsConnected(p)`) → `max(device, fallback)`, else fallback. `IsConnected` = `IsDeviceConnected` or fallback. Forwards device `OnConnected/OnDisconnected` (used players only). Always reads fallback each call (keeps simulator ramp advancing). Does **not** dispose the device. Used by `ArduinoSerialReader` and the window's `実機` with `fallback = GripInputBridge.Simulator`, so keyboard always works alongside hardware. Tested (`CompositeGripTransportTests`). |
| `ReplayGripTransport` | `(string jsonlPath)` | Loads all `GripLogEntry` lines; plays `raw` values by wall-clock (`Stopwatch` started in ctor) — feed goes through current filter/calibration again. `Restart()`. Connected iff player has samples. |

### Serial protocol (`GripSerialProtocol`, pure, tested)
- Line formats (trimmed): `"<int 0-1023>"` → P1 (simple, Arduino Uno 10-bit); `"a,b[,c[,d]]"` (≤4 ints 0-1023) → P1..P4 (`TryParseSamples`); `"G,<player 0-3>,<raw 0-4095>,<deviceMs>"` (spec format, 12-bit). Invalid lines → false (skipped). `BuildLine(p, raw, ms)` builds G-format. Constants `RawValueMax=4095`, `SimpleFormatRawValueMax=1023`.

## 6b. LAN relay — one Arduino (4 sensors) shared by 4 PCs (2026-10-22, exhibition setup decided by the user)
**Why**: at the exhibition ONE Arduino with all 4 grip sensors is plugged into ONE PC, and 4 PCs play co-op over LAN (each player in front of their own PC, no keyboard). The game was built assuming one sensor per PC read as local P1. Instead of changing the game/network code, the PC with the Arduino **broadcasts all 4 values on the LAN**, and every PC takes **its own sensor number** as its local P1. Everything downstream (title start, character select, `TurretNetworkHub` sending the local grip to the host, result, local gauge) is unchanged and does not know where P1 comes from. Seats (turret colours, assigned in arrival order by the auto-connect) don't matter: the binding is *sensor ↔ PC*, and the PC drives whatever turret it was given.
- **Enable**: launch option `-grip-sensor N` (1–4; also `-grip-sensor=N`, case-insensitive). Absent → relay off, behaviour exactly as before (no sockets). Invalid (5, -1, text, missing) → relay off + `Debug.LogError` + orange line in F8 (`RelayOptionsError`). `-grip-relay-send` = test sender: broadcast this PC's keyboard Q/W/O/P as sensors 1–4 without an Arduino (requires `-grip-sensor`). `-grip-relay-port P` = base port (default **47781**; sensor n listens on `P + n − 1`, so 47781–47784; valid 1024–65532). In the Editor only: `ArduinoSerialReader.editorRelaySensorNumber` (0 = off) / `editorRelayForceSend` override the command line (fields are always serialized; applied only when `Application.isEditor`, to avoid #if-serialization layout mismatches). Desktop shortcuts: `Tools/Exhibition/make_sensor_shortcuts.bat` (put next to `MS2026.exe`, or drag the exe onto it, or run from the project → `Builds\TestBuild`); spare PC = double-click the icon with the broken PC's number.
- **Startup** (`ArduinoSerialReader.Start`, both `#if` branches, after `DeferToPersistent`/overlay): `StartRelay()` → `GripRelayOptions.Parse(Environment.GetCommandLineArgs(), relayBasePort)` → if enabled `new GripRelaySession(options, relayTimeoutSeconds=0.5, relaySendRate=60)` and `GripInputBridge.SetTransport(session.Transport)` **once** (the persistent Title reader → active from the title screen, before any game connection). `Transport = CompositeGripTransport(RelayedSensorTransport(N−1, state), Simulator, devicePlayerCount: 1)` → local P1 = sensor N (local Arduino first, else the LAN value) max keyboard Q; P2–P4 = keyboard only (so other people's grips never operate this PC's title/menus). `devicePlayerCount` is ignored in relay mode.
- **Local Arduino**: `Install` in relay mode does **not** call `SetTransport`; it calls `session.SetLocalDevice(serial)` (→ this PC starts broadcasting and takes its own P1 directly from the device). `Uninstall` (USB lost) → `SetLocalDevice(null)` (broadcast stops; own P1 falls back to the LAN value — e.g. Arduino moved to a spare PC — or keyboard). Port search/re-plug recovery (§6) is unchanged, also on PCs without an Arduino (they keep searching every `portRetrySeconds`). `OnDestroy` → `SetLocalDevice(null)` then `StopRelay()` (restores `Simulator` only if `CurrentTransport` is still the session's transport; disposes threads/sockets, ≤ ~1 s).
- **Who broadcasts**: a PC broadcasts only while it has an installed Arduino (`SetLocalDevice`) or `-grip-relay-send`. `GripRelaySampleBuilder.Fill` decides the content. Packet per sensor: `Raw` = `max(device.GetRawValue(i), keyboard i)` (after the sensor conversion, before filter/calibration — each receiving PC applies its own provider filter/calibration), `Received` = pre-conversion value (diagnostics), `Connected` = `device.IsConnected(i)` (heartbeat 1000 ms). Test sender: all 4 = keyboard, Connected = true, `ForcedTestSender` flag. Keyboard values are pushed from the main thread in `session.Tick()` (called first in `ArduinoSerialReader.Update`) via `Volatile`.
- **Sender** (`UdpGripRelaySender`): own background thread, 60 Hz schedule (`nextSend += interval`, so Windows' ~15.6 ms Sleep granularity still averages ~60/s; measured 45–75 in the loopback test), independent of the host PC's frame rate. Targets rebuilt every 2 s (`GripRelayNetwork.BuildTargets`): for each of the 4 ports → `255.255.255.255`, each up IPv4 interface's directed broadcast, and `127.0.0.1` (same-PC instances). Same approach as `LanDiscovery` (proven between PCs). Unreachable targets are skipped silently; other send errors warn once. ~1 KB/packet-burst, ≈ 16 datagrams × 60/s of ~76 bytes.
- **Packet** (`GripRelayCodec`, little-endian, max 76 bytes): `"MSGR"` · version `1` · flags (bit0 test sender) · senderId u32 (random per process) · sequence u32 · count `4` · per sensor [raw u16 (0–65535 ↔ 0–1) · received u16 · status u8 (bit0 connected)] · name length u8 + UTF-8 machine name ≤ 40 bytes (truncated on char boundaries). Wrong magic → ignored; wrong version → counted (`WrongVersionPackets`, warning "全部のPCを同じビルドに"); bad length → malformed.
- **Receiver** (`UdpGripRelayReceiver`): one socket per PC on its own sensor's port (bound `IPAddress.Any`, `ExclusiveAddressUse` best effort, no ReuseAddress) → a second game with the same sensor number on the same PC gets `ListenError` "UDP … を使えません…" (logged as error, shown in F8). Background thread, `ReceiveTimeout` 250 ms, ignores ConnectionReset/MessageSize. Feeds `GripRelayReceiverState`.
- **State rules** (`GripRelayReceiverState`, lock-protected, injected clock): own senderId ignored; same sender → accept only if `(int)(seq − last) > 0` (dedupes the multiple copies, handles wrap); different sender while the current one is fresh → ignored and remembered as `OtherSender` (warning "放送が2か所から届いています") **unless** the current one has no connected sensor and the new one has (Arduino moved to a spare while the old PC still runs) → switch; current stale (> timeout) → switch. Values are usable only while fresh (≤ `relayTimeoutSeconds`, default 0.5 s) and the sensor's `Connected` bit is set; otherwise 0 (local keyboard only).
- **Overlay (F8)** extra lines (`ArduinoSerialReader.RelayStatus` → `GripRelayStatus`): `LAN: このPCはセンサーN番（UDP p） 握力の出どころ: このPCの Arduino / LAN の放送 / なし`, `放送: …放送中 n 回/秒 / 放送していない`, `受信: <machine> から n 回/秒 x秒前` or orange `放送が届いていません…`, `LAN の4人分（raw）: 1:0.12 2:— …`, orange lines for ListenError / two senders / wrong version / option errors. Panel width is now 1000 (1080p units).
- **Firewall/LAN**: Windows rules created by the first-run prompt are per program (all ports), so the already-allowed `MS2026.exe` needs no new prompt; a venue network classified as *Public* blocks it exactly like the game connection (switch the profile to Private). Works on a plain switch without IP setup (APIPA addresses share a subnet). If the 4 PCs auto-join one room, broadcasts reach them too.
- **Latency**: Arduino → PC1 serial thread → sender thread (≤ 16 ms) → LAN (< 1 ms) → receiver thread → next frame on the player's PC → `TurretNetworkHub` as before. Roughly +1 frame vs. a sensor plugged into the player's own PC.
- **Not covered / known**: if the Arduino PC dies, every player's grip drops to 0 (inherent to the hardware layout; the game itself keeps running). HUD `player.N.grip` for other players is still only correct for the local player (pre-existing, see FortressUiKeys description). Not verified yet: Unity Play, builds on 2+ real PCs, real Arduino.

## 8. Gotchas (current implementation gaps — mention when relevant, don't "fix" silently)
1. Calibration profiles are only applied right after saving in the window; **not loaded on Play start or in builds**. No runtime loader exists.
2. `GripFilterSettings` never applied → no noise filtering in practice.
3. `GripDeviceStatus.Stale/Suspicious`, `autoAssignPlayerIndex`, `SerialGripTransport.OnDisconnected` unused.
4. Serial `OnConnected` invoked on background thread — don't touch Unity API in handlers.
5. COM port must be released (Dispose); Arduino IDE serial monitor blocks the port.
6. Baud defaults differ: ArduinoSerialReader 9600 vs GripDeviceConfig 115200; heartbeat 1000 vs 200 ms.
7. Simulator uses `Time.deltaTime` (scaled) and `Keyboard.current` (Game view focus needed).
8. Replay plays raw values; filter/calibration are re-applied (intended for A/B tuning).
9. Recording writes 4 lines per frame (`{"t","p","raw","filtered","normalized"}`), AutoFlush off — call `StopRecording()` to flush.
10. The transport is a single global slot (last `SetTransport` wins). Undo only your own install (compare `CurrentTransport`), and never replace the input with a transport that has no data (check `SerialGripTransport.IsPortOpen`).
11. `CompositeGripTransport` forwards the serial `OnConnected` as-is, so it can also arrive on the background thread.
12. LAN relay (§6b): only active with `-grip-sensor N`. Do not call `GripInputBridge.SetTransport` elsewhere while it runs (it would bypass the relay). Members of `IGripRelayDevice` are read from the sender thread → must stay thread-safe (no Unity API). Sensor number = desk/cable number, not seat/turret number.
