    UISTUDIO

    UIスタジオ — 画面を重ねて、動かして、ゲームの値とつなぐ

    ロビーもHUDも、雛形を押すだけで動き出す。
    あとは見た目を自分の絵に差し替えるだけ。

    紙芝居の舞台を想像してください。奥から「背景の板」「HUDの板」「メニューの板」「ポップアップの板」…と何枚も重なっていて、それぞれの板に画面（紙）を出し入れします。UIスタジオは、この板（レイヤー）と紙（画面）の出し入れ、紙が出る・消えるときの動き、板を全部覆う幕（画面切り替え）、そして「熱が上がったらゲージを伸ばす」といったゲームとのつながりを、プログラムなしで決める道具です。

    誰が使う
    デザイナー（見た目・動き）／プランナー（画面の流れ・表示する値）
    開き方
    Tools›UIスタジオ›UIスタジオを開く
    必要なもの
    特になし（D-Drive の起動オブジェクトがシーンにあると動きが付く）
    今の状況
    2026-10-06 に完成。Unity上での動作確認はこれから（下の注意を参照）
    01 — What you can do

    作る・重ねる・動かす・
    つなぐ。

    ▢

    雛形からすぐ動く画面

    ロビー（4人の接続待ち）・ゲーム中HUD・確認ポップアップ・空の画面。値のつなぎ・動き・ボタンの役目まで入った状態でできあがります。

    例：ロビーを作って Play → P1を選んで「ホストになる」→ 幕が閉じて HUD に切り替わる

    ☰

    Photoshop風のレイヤー

    部品を「上ほど手前」で一覧。編集中だけ隠す・ゲームで隠す・ロック・↑↓で重なり順・グループ・濃さ。

    〰

    59種の動きをクリックで試す

    「ポンと出る」「ぷにっ」「ぶるっと震える」…を、Playせずに部品の上で再生。気に入ったら「出たとき」「押したとき」などに付けるだけ。

    ◧

    画面切り替えの幕

    暗転・ワイプ・まるく閉じる・ブラインド・ひし形・ルール画像・灼ける（ふちが光りながら焼ける）。カードの中で動く見本を見比べられます。

    ≡

    ゲームの値と線でつなぐ

    熱・オーバーヒート・コアのHP・敵の数・接続状況などが一覧に。部品にどれを出すか選ぶだけ。サンプル値を動かせば Play しなくても見え方がわかる。

    ✓

    点検と「直す」

    名前の重なり・値の打ち間違い・押せない透明な画像・役目の無いボタンなどを見つけ、多くは押すだけで直ります。

    デバッグ開発用の表示（一番手前）
    画面切り替え幕（ワイプ等）。自動で使われる
    通知「P2が参加しました」など
    ポップアップ確認・ポーズ（後ろを暗くして押せなくする）
    メニュータイトル・ロビー・リザルト（一度に1枚）
    HUDゲーム中ずっと出ている表示

    02 — First 5 minutes

    ロビー → HUD を
    5分で動かす。

    1

    UIの置き場所を作る

    Tools›UIスタジオ›UIスタジオを開く。上の帯の UIの置き場所を作る を押すと、ヒエラルキーに [UI] ができます（レイヤーごとの板・ゲームの値の書き込み役・EventSystem も一緒に）。

    UIスタジオ
    ☑ サンプル値で表示
    編集中の画面なし
    UIの置き場所を作る
    2

    雛形でロビーとHUDを作る

    左の 画面 ページで ロビー（4人の接続待ち） と ゲーム中HUD のカードを1回ずつ押します。Lobby と Hud という名前の画面ができ、一覧に入ります。

    画面
    □ 空の画面◎ ロビー▮ ゲーム中HUD▢ 確認ポップアップ
    メニュー ● ロビー〔起動時〕
    HUD ● ゲーム中HUD
    3

    Play して、ホストになる

    ▶ Play。ロビーが出たら P1 のカードを押して ホストになる。つながると幕が閉じて、HUD に切り替わります。Q を押すと熱ゲージが伸び、オーバーヒートで OVERHEAT が震えて点滅します。

    4

    見た目を自分の絵にする

    画面ページで HUD を選び この画面を編集。シーンビューで部品を動かし、画像の Source Image に自分の絵を入れるだけ。レイヤー ページで重なり順やグループを整理できます。

    レイヤー › 部品（上ほど手前）
    ◎ ● □ ▤ Overheat 〔値〕〔動〕 ↑↓
    ◎ ● □ ▤ CoreHp ↑↓
    ◎ ● □ T Enemies 〔値〕 ↑↓
    ◎ ● □ ▤ LocalHeat ↑↓
    濃さ（初期値）
    5

    動きを足して、点検

    動き ページで部品を選び、定番の動き をクリックして試し、付ける。最後に 点検 ページで赤が0なのを確かめます。

    これでロビー → HUD の流れができました。あとは絵と動きを好みに。

    今の状況の注意（2026-10-06）：コードの組み立て（コンパイル）と計算部分の自動テストは通っていますが、Unity の中で画面・幕・雛形を動かす確認はまだです。崩れていたら開発者（Claude）に伝えてください。今の仮の接続画面（右上）と仮の熱ゲージ（下）は残してあります。ロビーが出ると仮の接続画面は止まり、HUD の段に画面が出ている間は仮の熱ゲージが自動で隠れます。今の Game シーンにそのまま [UI] を足して試せます（既存の物は変わりません）。
    03 — Recipes

    「〜したい」から
    探す。

    ボタンで別の画面を開きたい・閉じたいボタンの役目

    ボタンに Add Component›UI Studio›ボタンの役目 (UiButtonAction) を付け、押したときにすること を選びます：OpenScreen（開く）／CloseScreen（閉じる）／CloseThisScreen（このボタンの画面を閉じる）／Back（戻る）／SwitchScreen（幕で切り替える）／LoadScene（幕でシーンを読む）／PlayMotion（名前の動き）。名前（画面・シーン・動き） に画面の名前（例 Hud）。点検に「押しても何も起きません」が出たボタンは、これを付ければ直ります。

    「本当にやめますか？」の小窓を出したい画面 › 確認ポップアップ

    画面ページの 確認ポップアップ で作ります（ポップアップの段・モーダルON＝後ろを暗くして押せなくする）。開くボタンには「ボタンの役目」で OpenScreen ＋ 名前 Confirm。はい・いいえ は最初から「この画面を閉じる」になっています。

    ゲームが始まったときに出す画面を決めたい画面の設定

    画面の設定の 起動時に開く をON。ロビーの雛形は最初からON、HUD はOFF（ロビーから切り替わる）。ロビーを使わずにすぐ遊ぶテストなら、HUD をONにしてロビーをOFFに。

    ポーズ画面をHUDより手前に出したい（重なり順）レイヤー

    画面の設定の レイヤー（段） で ポップアップ を選ぶとHUDより手前。段そのものの順番はレイヤーページの帯の ↑↓ で入れ替えます。同じ段の中は「後から開いた画面が手前」。

    部品がポンと出る・押したらぷにっとする動きを付けたい動き
    1. 動きページで部品を選ぶ（レイヤーページかシーンビューで選ぶ）。
    2. 定番の動き の名前をクリック → その場で動く。
    3. 右上のきっかけ（出たとき・押したとき…）を選んで 付ける。
    4. 順番に出したいときは、部品ごとに 遅らせる（秒） を少しずつ増やす（0.05〜0.1 秒ずつがおすすめ）。
    オーバーヒート中だけ「OVERHEAT」を点滅させたい値で表示を切り替える＋動き

    HUD の雛形の作りをまねします：外枠に 値で表示を切り替える (UiBindVisible)（見る値 local.overheated、WhenOn）、中の文字に動き ずっと繰り返す ＋ 点滅。同じ部品に両方付けないのがコツです（どちらも透明度を使うため）。

    画面切り替えをワイプや「灼ける」にしたい画面切り替え

    画面切り替えページのカードで見比べ、使いたい幕を、ボタンの役目（SwitchScreen / LoadScene）の 画面切り替えの幕 か、ロビー画面の動きの 画面切り替えの幕 に入れます。色・秒数・向きは選んだ幕の設定で。▶ Playで試す で本物を確認。

    自分で描いた模様で画面を切り替えたいルール画像

    白黒の画像（暗い所から先に覆われる）を用意し、新しい幕の 模様 を RuleTexture、ルール画像 にその画像を入れます。グラデーションや渦巻き・手描きのムラなど、自由な切り替えが作れます。

    ゲームの値をゲージや数字で出したい値のつなぎ
    1. 部品に Add Component›UI Studio から 値をゲージで出す（UiBindFill）／値を文字で出す（UiBindText）／値で色を変える（UiBindColor）／値で表示を切り替える（UiBindVisible）。
    2. 見る値 の ▼ で値を選ぶ（例：コアのHP（割合））。
    3. 文字は 書式 で飾れます：{0:0}% → 70%、敵 {0:N0} → 敵 1,200。

    ゲージは画像の Image Type を Filled にするのがおすすめ。残像の画像 に色違いの画像を入れると、減ったときに遅れて追いかける「残像」になります。

    Playせずにゲージの見え方を確かめたい値・サンプル値

    上の帯の サンプル値で表示 をON。値ページで各値の サンプル値 のスライダーを動かすと、シーンビューのゲージや文字がその場で変わります。隠れる部品（UiBindVisible）は、編集中は薄く表示されます。

    新しい値（スコアなど）を画面に出したい値

    値ページの ＋ 値を足す で名前と説明を決め、プログラマーにその名前で書き込んでもらいます（UiValues.Set("score", 1200) の1行）。部品側はその名前を選ぶだけ。

    ロビーで別のPCに参加したいロビー

    ホスト役のPCで P1 などを選んで ホストになる。参加するPCでは別の番号を選び、ホストのIPアドレス にホストのPCのIP（例 192.168.0.12）を入れて 参加する。各カードの 参加中 はホストのPCでは全員分、参加側では自分だけ表示されます（今の通信の仕組みでは参加側に他の人の接続状況が届かないため）。

    間違って作った画面を消したい画面 › この画面を削除
    1. 画面ページの一覧で、消したい画面を選ぶ（同じ名前が2つあるときは、プロジェクトで見る でどのファイルか確かめる）。
    2. 下の この画面を削除 を押し、確認で 削除する。
    3. 画面の一覧から外れ、Prefab ファイルはパソコンのごみ箱へ移ります。間違えたら、ごみ箱から元の場所へ戻せば復活します（一覧には 画面 ページから入れ直す）。ファイルを残して一覧からだけ外したいときは 一覧から外す。
    文字を TextMeshPro にしたい（縁取り・影を付けたい）画面 › 文字を TextMeshPro にする
    1. ゲームに入れてよいライセンスの日本語フォント（.ttf / .otf）をプロジェクトに入れる（Windows に入っているメイリオ等は、ゲームに同梱してよいか必ず確認）。
    2. 画面ページで画面を選び、文字を TextMeshPro にする（任意） の 日本語のフォントファイル に入れて TextMeshPro 用のフォントを作る（使った文字だけ自動で足されるので、文字の一覧を用意しなくてよい）。
    3. この画面の文字を TextMeshPro にする。文字・大きさ・色・寄せ方はそのまま置き換わります（入力欄の中の文字は除く）。Prefab の画面は元に戻せないので、先に 複製 しておくと安心。

    見つかりませんでした。別の言葉で探してください。

    レイヤー

    ⏱ 重なり順・部品を整理するとき
    • 上：画面の重なり（段の帯、↑↓、Canvas をそろえる、レイヤーの一覧の編集）。
    • 下：部品（上ほど手前）。◎=編集中だけ隠す（ゲームに影響なし）、●=ゲームでも表示、⊠=シーンで選べなくする（ロック）、↑↓=重なり順、札 値／動。
    • ボタン：＋ グループにまとめる・グループを解く・複製・削除。選んだ部品の 名前・濃さ（初期値）。

    動き

    ⏱ 出る・消える・押したときの動きを付けるとき
    • 選んだ部品の動き：きっかけ・動き・長さ（秒・0=標準）・強さ・距離（0=標準）・遅らせる（秒）・効果音・見る値（値が増えた／減ったとき）・▶ 試す・消す。
    • 定番の動き（出る／消える／ずっと繰り返す／目立たせる）：クリックで試す → きっかけを選んで 付ける。
    • 画面全体：出るときの動き・消えるときの動き、▶ 出る動きを試す など。

    画面切り替え

    ⏱ 画面・シーンの切り替え演出を決めるとき
    • 幕のカード（小さな画面で見本が動く）、＋ 新しい幕、ひな形をそろえる。
    • 選んだ幕：▶ Playで試す・複製、設定（模様・幕の色・閉じる秒数・開く秒数・向き（度）・開くとき同じ向きへ抜ける・ルール画像・灼けるふちの色・効果音…）。

    値

    ⏱ ゲームのどの値を画面に出すか決めるとき
    • ゲームの値を一覧に登録（熱・コア・敵・通信・ロビーの値をまとめて登録）、＋ 値を足す。
    • 各値：表示名・名前（クリックでコピー）・○か所で使用・説明・サンプル値・Play中の今の値・名前や種類の編集。

    点検

    ⏱ Playする前
    • 主な点検：置き場所が無い／設定ファイルが無い／画面の名前が無い・重なっている／レイヤーが無い／値の名前が一覧に無い（打ち間違い？）／見えないのにクリックを受け止める画像／押しても何も起きないボタン。

    06 — Troubleshooting

    困ったときは
    ここ。

    動きが付かない（パッと出る・消える）
    動きの中身は D-Drive なので、シーンに D-Drive の起動オブジェクト（[D-Drive] Runtime）が必要です。無いときは動きを飛ばして、すぐ出る・消えるようになっています。
    ボタンを押しても何も起きない
    「ボタンの役目」を付けたか、EventSystem があるか（Play時に無ければ自動で作ります）、手前に見えない画像が被さっていないか（点検の「見えないのにクリックを受け止めています」）を確認。
    ゲージや文字が動かない
    部品の 見る値 が値の一覧にあるか（黄色なら打ち間違い）。[UI] に「ゲームの値を画面へ (FortressUiValues)」が付いているか（点検で直せます）。
    編集中に部品が薄く表示される
    「値で表示を切り替える」の付いた部品が、サンプル値では「隠れる」状態です。編集しやすいように薄く見せています。値ページでサンプル値を変えると表示されます。
    HUD と昔の熱ゲージが二重に出る
    [UI] に 仮の表示との切り替え (FortressLegacyUiSwitch) が付いていれば、HUD の段に画面が出ている間は仮の熱ゲージ（[Fortress] LocalTurretHud）が自動で隠れます。付いていなければ点検の「仮の熱ゲージとの切り替え部品がありません」の 部品を付ける。
    テスト用の bat で起動したらロビーが出たままになる
    起動引数で自動でつながった場合も、つながった時点でロビーは HUD に切り替わります。ロビーを出したくなければ、ロビーの 起動時に開く を OFF に。
    日本語の文字が四角（□）になる
    TextMeshPro の文字の部品は日本語のフォントが必要です（TextMeshPro にするレシピ）。雛形は標準の Text なので、そのままで日本語が出ます。
    07 — Words

    分からない言葉は
    ここで引く。

    画面
    ロビー・HUD・ポーズなど1枚の画面。名前で開け閉めする。
    レイヤー（段）
    画面の重なりの段。上の段ほど手前に出る。
    部品
    画面の中の画像・文字・ボタン・ゲージ。
    値
    ゲームから画面へ渡す数・文字・色。名前（例 local.heat）で選ぶ。
    サンプル値
    Playしていないときに見た目を確かめるための仮の値。
    動き
    出る・消える・押した…ときのアニメ。D-Drive の UI の動きを使う。
    幕（画面切り替え）
    画面やシーンを入れ替えるとき、全体を覆って隠す演出。
    モーダル
    その画面が出ている間、後ろの画面を押せなくすること。
    Prefab の編集画面
    画面のファイルを開いて中身を直す、Unity の専用の編集モード。
    08 — For programmers

    呼ぶのは
    名前だけ。
