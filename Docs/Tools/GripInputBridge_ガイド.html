    GRIP INPUT握力入力ブリッジ

    Grip Input Bridge ＆ Simulator — 握力センサーとゲームのあいだの通訳

    センサーの「生の値」を、
    ゲームが使える 0〜100% の握力 に整える。
    センサーが無くても キーボードで動く。

    センサーは個体差もノイズもあるし、子どもと大人で握力も全然違います。それを毎回「この人にとっての 0〜100%」に通訳してゲームに渡すのがこのツールです。ゲーム側は通訳済みの数字だけを見ればいい、という仕組みです。

    誰が使う
    全員（開発中のテスト）／本番当日の運営スタッフ（キャリブレーション・監視）
    開き方
    Tools›握力入力ブリッジ›ウィンドウを開く
    キー
    P1 Q　P2 W　P3 O　P4 P（押しっぱなしで握力が上がる）
    ウィンドウ無しでも
    Play するだけでキーボード入力は自動で有効。ウィンドウは「見る・調整する」ための道具です
    01 — What it does

    握った力が
    ゲームに届くまで。

    握力は次の順番で「通訳」されて、最後にゲーム（砲台のレーザー）へ届きます。どの段階も、このツールで確認・調整できます。

    FROM HAND TO LASER
    1 · 入力元
    センサー or キーボード or 記録
    どこから値を取るか。いつでも切り替えられる。
    2 · ノイズ除去
    ガタつきを取る
    一瞬だけ跳ねた値などをならす（設定した場合）。
    3 · キャリブレーション
    その人の 0〜100% に
    その人の最大握力を 100% として換算。子どもも大人も対等に。
    4 · 判定
    握った／離した
    12% を超えたら「握った」、8% を下回ったら「離した」。
    5 · ゲーム
    レーザーの太さ・熱
    砲台がこの 0〜100% を毎フレーム読む。
    ⌨️

    シミュレータ

    キーボードで 4 人分の握力を代用。押すと上がり、離すと下がる「握ってる感じ」の動き。

    使う場面 センサーが無い普段の開発

    〰️

    波形プリセット

    「そっと／しっかり／渾身／リズムテスト」の握り方を自動で再生。手を使わずに試せる。

    使う場面 渾身で何秒でオーバーヒートするか見る

    🎯

    キャリブレーション

    プレイヤーごとに 3 秒全力で握ってもらい、その人の 100% を記録する。

    使う場面 本番で来場者ごとに

    🩺

    診断

    4 人分の接続状態と現在の値を一覧。ケーブル抜けなどにすぐ気づける。

    使う場面 展示本番の監視

    ⏺️

    記録と再生

    握力の動きをファイルに記録して、あとで同じ動きを再生できる。

    使う場面 本番で起きた不具合の再現

    🔌

    実機（Arduino）

    USB でつないだマイコンのセンサー値を受け取る。最大 4 人分。

    使う場面 筐体での実プレイ

    03 — Recipes

    「〜したい」から
    探す。

    展示：1 台の Arduino（4 人分のセンサー）を 4 台の PC で使いたいLAN で配る › -grip-sensor

    しくみ：Arduino をつないだ PC が、4 人分の握力を LAN へ放送します（1 秒に約 60 回）。どの PC も 4 人分を受け取りますが、使うのは自分の席の番号のセンサーだけで、それを「この PC の前の人の握力」としてタイトル・キャラ選択・砲台・リザルトに使います。ゲームの接続（部屋さがし）とは別なので、タイトルの時点から握ってスタートできます。席（砲台の色）が来た順で決まっても、握る人・見る画面・動く砲台は同じ PC の中でつながるので、ずれません。

    1. 配線の番号＝席の番号：Arduino が送る a,b,c,d の順（例：A0〜A3）がセンサー 1〜4 です。ケーブルと机に同じ番号を書いておきます。
    2. アイコンを作る（PC ごとに 1 回）：ビルドのフォルダ（MS2026.exe のある所）に Tools\Exhibition\make_sensor_shortcuts.bat と make_sensor_shortcuts.ps1 をコピーしてダブルクリック。デスクトップに「MS2026 センサー1で起動」〜「センサー4で起動」の 4 つができます。予備の PC にも作っておきます。
    3. 起動：各 PC で、その机の番号のアイコンをダブルクリック。Arduino をつないだ PC も同じです（例：机 1 なら「センサー1で起動」）。Arduino がつながった PC は自動で放送係になります（設定はいりません）。
    4. 確認：各 PC で F8。「LAN: このPCはセンサー3番」「受信: ○○ から 60 回/秒」と出て、その席のセンサーを握ると「LAN の4人分」の 3 の数字が動けば OK。

    予備の PC に替えるとき：壊れた PC と同じ番号のアイコンをダブルクリックするだけ（マウスだけでできます）。Arduino をつないだ PC が壊れたら、Arduino の USB を予備に挿し替えて同じ番号のアイコンで起動します。ほかの PC は、放送が戻ると自動でまた受け取ります（放送が 0.5 秒以上止まると、その間は全員の握力が 0 になります）。

    !
    LAN とファイアウォール：放送は UDP 47781〜47784 を使います。Windows の許可は MS2026.exe ごとなので、ゲームの接続（7777・部屋さがし 47777）が通っている PC では新しい確認画面は出ません。ただし会場で LAN につないだとき Windows がそのネットワークを「パブリック」と判断すると止まることがあるので、各 PC のネットワークを「プライベート」にしてください（初回の許可画面では両方にチェックしておくと安心）。4 台が 1 つの部屋にまとまってキャラ選択に入れたら、放送も届くと考えてかまいません（同じ仕組み）。

    アイコンを使わずに起動するときは、起動オプション -grip-sensor 3（3 = 席の番号）を付けます。付けなければ今まで通り（各 PC の Arduino をその PC の P1 として使い、LAN では配らない）です。

    展示の「LAN で配る」を、1 台の PC（Arduino なし）で試したい-grip-relay-send
    1. ビルドした MS2026.exe を 4 つ起動します。1 つ目だけ -grip-sensor 1 -grip-relay-send、残りは -grip-sensor 2／3／4（Alt+Enter でウィンドウにできます）。-grip-relay-send は「Arduino が無くても、この PC のキーボード QWOP をセンサー 1〜4 として放送する」テスト用のオプションです。
    2. 1 つ目のウィンドウを選んで W を押すと、2 つ目（センサー 2）の握力として届きます。タイトルのスタート・キャラ選択・砲台が 2 つ目で動けば OK。
    3. bat で試すなら、run_instance.bat の最後に付け足します（例：run_instance.bat host 0 - -grip-sensor 1 -grip-relay-send、run_instance.bat client 1 - -grip-sensor 2）。

    Unity の中で試すときは、タイトル（またはゲーム）のシーンの ArduinoSerialReader の Editor Relay Sensor Number に番号、Editor Relay Force Send を ON（エディタの中だけ効きます）。同じ PC で同じ番号を 2 つ起動すると、2 つ目は「UDP ○ を使えません」と出て受け取れません。

    4 人同時に握った状態を試したいシミュレータ

    QWOP を同時に押しっぱなしにします。手が足りなければ、何人かを 波形プリセット（そっと／しっかり／渾身）にして自動で握らせます。

    「そっと」「しっかり」「渾身」の強さで試したいシミュレータ
    • そっと：20〜30% をゆらゆら維持
    • しっかり：50〜60% を維持
    • 渾身：90〜100% を維持（オーバーヒートの確認に）
    • リズムテスト：0.4 秒ごとに 80% と 0% を交互に（握る／離すの繰り返し）

    なし(キーボード操作) に戻すとキー入力に戻ります。

    本番で来場者ごとにキャリブレーションしたいキャリブレーション
    1. Play 中に「キャリブレーション」タブを開く。
    2. プレイヤー で P1〜P4 を選ぶ。
    3. 計測開始(3秒間、最大握力で握ってください) を押し、カウントダウンの間ずっと全力で握ってもらう。
    4. 「計測結果(最大値): 0.xxx」が出たら この結果を保存。

    これでその人の全力が 100% になり、握力が弱い人でも太いレーザーが出せるようになります。

    !
    今の仕様の注意：保存した結果は「保存したその Play の間」だけ反映されます。Play をやり直したときや、ビルドしたゲームでは自動で読み込まれません（読み込みはまだ未実装）。その都度キャリブレーションし直してください。
    本番中にセンサーが抜けていないか見張りたい診断

    「診断」タブに 4 人分の 状態 と 現在の値 が並びます。Connected 以外（Disconnected など）が出たら要確認。実機は、一定時間（設定では 200ms、Arduino 用コンポーネントでは 1000ms）データが来ないと「切断」とみなします。

    センサーが壊れたので、その人だけキーボードで代用したい入力元

    上部の 入力元 を シミュレータ に切り替えると、Play を止めずに全員キーボード入力になります（切り替えは 4 人まとめて）。実機に戻すときは 実機 を選び直します。

    プレイ中の握力の動きを記録して、あとで再現したいREC / 記録再生
    1. 上部の ● REC を押すと記録開始（ボタンが ■ 停止 に変わる）。保存先は Console に表示されます。
    2. もう一度押すと記録終了。ファイルはプロジェクト直下の GripLogs/日付_時刻_session.jsonl。
    3. 再現するときは 入力元 を 記録再生 にして、そのファイルを選ぶ。記録したときと同じタイミングで握力が再生されます。

    再生されるのは「通訳前の生の値」なので、キャリブレーションや設定を変えて「同じ握り方で結果がどう変わるか」を比べられます。

    Arduino のセンサーをつなぎたい実機
    1. Arduino IDE の シリアルモニタは閉じる（開いているとポートを取り合って Unity から読めません）。
    2. シーンの適当な GameObject に ArduinoSerialReader コンポーネントを付ける。
    3. Port Name に COM ポート（Arduino IDE の「ツール › ポート」で確認、例 COM3）、Baud Rate にスケッチの Serial.begin(…) と同じ値（既定 9600）。
    4. 磁石で反応するホールセンサー（49E など）なら Centered Sensor を ON（何もしていないとき約 512 を出すタイプ）。
    5. ▶ Play。Log Values が ON なら Console に P1: arduino=… raw=… grip=… が流れます（実機につながっている間だけ。つながっていないときは出ません）。

    実機につないでいる間もキーボード（Q/W/O/P）は効きます。COM ポートを開けなかったとき（デバイスを挿していない等）は「キーボードシミュレータのまま動かします」と警告が出て、キーボードだけで遊べます（デバイスが無い PC でも同じビルドが使えます）。

    ポートの番号が PC ごとに違っても大丈夫（2026-10-12）：Auto Find Port（既定 ON）なら、Port Name のポートで値が届かないとき、PC にある COM ポートを全部同時に試して、値が届いたポートを使います（Console に「握力デバイスのポートをさがしています（COM5, COM3…）」→「COM3 (9600bps) を入力元にしました」）。どこからも届かなければ「値が届くポートがありませんでした」と出てキーボードのまま動き、Port Retry Seconds（既定 5 秒）ごとにさがし直します（展示中に USB を挿し直したとき用）。さがしている間もキーボードは効きます。

    USB を挿し直しても大丈夫（2026-10-12）：使っているポートから Device Lost Seconds（既定 3 秒）のあいだ値が届かない・ポートが使えなくなったら（USB が抜けた・デバイスが止まった）、Console に「値が届かなくなりました」と出てキーボードに切り替わり、ポートをさがし直し続けます。挿し直すと数秒（さがし直す間隔＋Uno の再起動）で自動で実機に戻ります。試合中・キャラ選択中でもゲームは止まりません。

    タイトルに置く物は「Keep Across Scenes」を ON：シーンが変わっても消えずに同じポートを使い続けます。ほかのシーン（ロビー・ゲーム）の ArduinoSerialReader は、これがあれば何もしません。シーンごとにポートを開け直すと、Arduino Uno は開くたびに約 2 秒再起動して値が途切れるためです。タイトルへの配置は Tools›タイトル›握力センサーの読み取りを置く で行えます（タイトル画面のガイド）。

    Arduino からは Serial.println(analogRead(A0)); のように 1 行に数値 1 つ（P1）、または 512,300 のように カンマ区切りで最大 4 つ（P1〜P4）を送れば OK です。

    実機の値でレーザーが出るのは、最初は P1 だけ（2026-10-20）：Device Player Count（既定 1）より後のプレイヤーは、Arduino が 512,300 のように 2 つ以上送ってきても実機の値を使わず、キーボードだけで動きます。1 台の PC で 2 人以上が実機で遊ぶときだけ、人数に合わせて増やしてください（下の「実機の値で P2 以降のレーザーまで出てしまう」）。

    実機の値で P2 以降のレーザーまで出てしまう／P2 も実機で動かしたい実機 › Device Player Count

    ArduinoSerialReader の Device Player Count で、実機の値を使うプレイヤーの数（P1 から数える）を決めます。

    • 1（既定）：P1 だけ実機。1 人プレイ・通信なしのときや、通信ありで各 PC が 1 人ずつのときはこれ。
    • 2〜4：1 台の PC に 2 人以上のセンサーをつなぐとき。
    • 0：実機を全員使わない（キーボードだけ）。

    Console に「COM3 (9600bps) を入力元にしました（実機の値を使うのは P1 だけ…）」と、今の設定が出ます。F8 の表では、実機を使わないプレイヤーの状態に「実機OFF」と付きます（届いた値は表示されますが、レーザーには使いません）。どのプレイヤーでもキーボード（Q/W/O/P）は効きます。

    設定はタイトルに置いた ArduinoSerialReader（Keep Across Scenes が ON の物）のものが使われます。ゲームのシーンの物を変えても効かないので注意。

    コントローラーから届いている生の値を画面で見たい実機 › F8
    1. ▶ Play 中（またはビルドしたゲーム）で F8 を押すと、画面の左上に表が出ます。もう一度 F8 で消えます。
    2. 上から 状態（受信中／ポートをさがしています など）、ポートと通信速度、受信（1 秒に何行届いているか・最後の行が何秒前か・届いた行の数・読めなかった行の数）。
    3. 届いた1行 は、コントローラーが送った文字をそのまま表示します（Arduino の println の行末の見えない文字は \r と表示）。形が合わず捨てた行があれば 読めなかった行 にも出ます。
    4. 下の 4 行は P1〜P4。届いた値(0-1023)・raw（センサー特性の変換後 0〜1）・grip（ゲームが使う最終の値 0〜1）・状態。届いた値の大きさが、プレイヤー色の帯で後ろに描かれます。値がまだ一度も来ていないプレイヤーは「—」。状態に「実機OFF」と付いたプレイヤーは、Device Player Count の外なので実機の値をレーザーに使いません。
    5. LAN で配る使い方（-grip-sensor N）のときは、さらに LAN:（この PC のセンサー番号・握力の出どころ＝この PC の Arduino／LAN の放送／なし）、放送:（この PC が放送しているか・回/秒）、受信:（どの PC の放送を何回/秒・何秒前に受け取ったか）、LAN の4人分（届いている 4 人分の値。届いていない番号は「—」）が出ます。困ったことはオレンジ色の行で出ます。

    始めから出しておきたいときは、ArduinoSerialReader の Show Raw Values を ON（エディタの中だけ。ビルドでは起動オプション -debug-ui を付けたときだけ効きます）。ビルドで確実に始めから出すなら、起動オプション -gripdebug。会場（キーボードなし）では何もしなければ出ません。

    見分け方：「受信 0.0 行/秒」なら値が来ていない（USB・ポート・通信速度を確認）。行は届いているのに「読めなかった行」が増えるなら、送っている文字の形が合っていません（512 や 512,300 のような 0〜1023 の整数が 1 行に最大 4 つ）。表が出ないときは、シーンに ArduinoSerialReader があるか確認（タイトルに置いた物がシーンをまたいで使われます）。

    何もしていないのに「握っている」になる実機
    • ホールセンサーなら Centered Sensor が ON か確認。OFF だと、何もしていないときの約 50% をそのまま握力と勘違いします。
    • ON なのにずれるなら、Sensor Center 01（何もしていないときの値。Uno の 512 なら 0.5）を Console の arduino= の値 ÷ 1023 に合わせます。
    • 小さなノイズは 3% 以下を 0 とみなす「デッドゾーン」で吸収しています。
    ウィンドウの「入力元：実機」を使いたい入力元

    ウィンドウの 実機 は、プロジェクト内の GripDeviceConfig アセットの設定で接続します。まだ無いので、Project ウィンドウで右クリック › Create›MS2026›Grip Input Bridge›Device Config で作り、Serial Port Name・Baud Rate（既定 115200）などを設定してください。普段の配線テストは上の ArduinoSerialReader の方が手軽です。

    ⏱ 握力をどこから取るか決めるとき

    • ● REC：記録の開始／停止。
    i
    ウィンドウを開いただけでは入力元は変わりません。シーンの ArduinoSerialReader が実機につないでいれば「実機」と表示されます。「実機」のときもキーボード（Q/W/O/P）と波形プリセットは使えます（実機とキーボードの大きい方が使われる）。

    シミュレータ

    ⏱ 普段の開発・テスト
    • P1〜P4 の 接続状態の点（色付き=接続中／灰色=未接続）、状態、握力バー（0〜100%、ゲームが実際に使う値）。
    • 波形プリセット：なし(キーボード操作)／そっと／しっかり／渾身／リズムテスト。
    • キーボード操作キー の表示（P1=Q、P2=W、P3=O、P4=P）。

    キャリブレーション

    ⏱ 本番で来場者が替わるたび（Play 中のみ）
    • プレイヤー：P1〜P4 を選ぶ。
    • 計測開始(3秒間、最大握力で握ってください)：3 秒のカウントダウン中の最大値を記録。
    • この結果を保存：Assets/_Tools/GripInputBridge/CalibrationProfiles/P1_CalibrationProfile.asset などに保存して、すぐ反映。

    診断

    ⏱ 展示本番中の見張り
    • 4 人分の 状態（Connected / Disconnected）と 現在の値 の一覧。入力元が実機のときは「実機 接続中」／「実機なし(キーボード)」と表示され、実機が来ていない人の行が警告色になります。
    • Connected 以外が出たら、ケーブル・電源・COM ポートを確認。

    06 — Troubleshooting

    困ったときは
    ここ。

    キーを押してもバーが上がらない
    1. Play 中か確認（Play していないと動きません）。
    2. Game ビューをクリックしてから押す。
    3. その人の 波形プリセット が「なし(キーボード操作)」になっているか（プリセット中はキーを無視）。
    4. 入力元 がシミュレータか実機か確認（記録再生中はキーが効きません）。
    実機の値が来ない（Disconnected のまま）
    1. Arduino IDE のシリアルモニタを閉じる（ポートの取り合い）。
    2. COM ポート名とボーレートが Arduino 側と一致しているか。
    3. Console に「シリアルポート 'COM3' を開けませんでした」が出ていないか。
    4. 前の Play がポートを掴んだままのことがあります。Play を止めてもう一度 Play、それでもダメなら Unity を再起動。
    5. Console に「キーボードシミュレータのまま動かします」と出ていたら、ポートを開けていません（上の 1〜3 を確認）。
    6. 「値が届くポートがありませんでした（試したポート: …）」と出たら、どのポートからも正しい形の値が来ていません。一覧にデバイスのポートが無ければ USB・ドライバ、あればボーレートと Arduino 側の送信を確認。
    7. 「前のシーンから残っている読み取りを使うので、ここではポートを開きません」は正常です（タイトルに置いた物が使われています）。
    8. F8 で生の値の表を出すと、値が届いているか（受信 行/秒）・届いた文字そのものが見られます（「コントローラーから届いている生の値を画面で見たい」）。
    9. 途中で「値が届かなくなりました」と出たら、USB が抜けたかデバイスが止まっています。挿し直せば自動で戻ります（戻らなければ Console の「値が届くポートがありませんでした」の試したポートを確認）。
    展示（LAN で配る）で、Arduino の無い PC の握力が動かない
    1. F8 を押して、オレンジ色の行を見る。
    2. 「放送が届いていません」：Arduino の PC が起動しているか、その PC の F8 で「放送: このPCの Arduino の4人分を放送中」になっているか。なっていなければ Arduino の USB を確認。なっていれば LAN（同じハブにつながっているか）と、各 PC のネットワークが「プライベート」になっているか（ファイアウォール）を確認。
    3. 「UDP ○ を使えません」：同じ PC で同じ番号のゲームが 2 つ動いています（1 つ閉じる）。
    4. 「放送が2か所から来ています」：Arduino をつないだ PC が 2 台あるか、-grip-relay-send を付けた PC があります。1 台だけにする。
    5. 「形の違う放送」：ビルドの違う PC が混ざっています。全部同じビルドにする。
    6. 受信は来ているのに動かない：「LAN の4人分」で自分の番号が「—」なら、Arduino がその番号のセンサーの値を送っていません（配線・スケッチを確認）。別の番号が動くなら、アイコンの番号と机の番号が合っているか確認。
    Console に「実機通信が無効のため…」と出る
    実機通信には Project Settings › Player › Api Compatibility Level を「.NET Framework」、Scripting Define Symbols に MS2026_GRIP_SERIAL_ENABLED が必要です。このプロジェクトでは Standalone（PC）向けに設定済みなので、別のビルド対象に切り替えていないか確認してください。設定の変更はプログラマーに相談を。
    キャリブレーションしたのに、次に Play したら元に戻った
    今の仕様です。保存したファイルは残りますが、次の Play では自動で読み込まれません。もう一度キャリブレーションするか、プログラマーに「起動時に読み込む処理」を追加してもらってください。
    値がガタガタ震える
    ノイズ除去の設定ファイル（GripFilterSettings）は用意されていますが、今は使われていません（何も通さずにそのまま値が届いている状態）。ガタつきが気になる場合は、プログラマーにフィルタ設定の適用を依頼してください（おすすめは既定の「メディアン → EMA」）。
    07 — Words

    分からない言葉は
    ここで引く。

    生の値 raw
    センサーから来たままの値（0〜1 に換算済み）。人によって最大値がばらばら。
    握力値 grip value
    通訳後の 0〜100%（0〜1）。ゲームが使うのはこれ。
    キャリブレーション
    その人の全力を測って 100% に合わせること。較正とも言う。
    デッドゾーン
    ごく小さい値を 0 とみなす範囲。ノイズで勝手に握った判定にならないように。
    のりしろ ヒステリシス
    「握った」と「離した」の境目をずらしておくこと。境目でふらついても判定がバタつかない。
    入力元 トランスポート
    値をどこから取るか。シミュレータ・実機・記録再生の 3 種類。
    COM ポート
    USB でつないだマイコンに Windows が付ける番号（COM3 など）。
    ボーレート
    シリアル通信の速さ。送る側と受ける側で同じにしないと読めない。
    ハートビート
    「生きてるよ」の定期的なデータ。一定時間途切れたら切断とみなす。
    放送 ブロードキャスト
    LAN につながっている全員に同じ物を送ること。展示では Arduino の PC が 4 人分の握力を放送し、各 PC が自分の番号の分だけ使う。
    センサー番号
    Arduino が送る 4 つの値の何番目か（1〜4）。展示では「机（ケーブル）の番号」と同じにして、各 PC の起動アイコンで指定する。
    UDP
    ネットワークで小さなデータを送るやり方の 1 つ。届いたか確かめない代わりに速い。握力の放送は 1 秒に約 60 回送るので、たまに 1 回落ちても困らない。
    ホールセンサー
    磁石の近さで値が変わるセンサー。何もしないと中間の値を出す。
    08 — For programmers

    ゲームから読むのは
    この 1 行。

    入口は静的クラス MS2026.GripInputBridge.GripInputBridge だけ。実機・シミュレータ・記録再生のどれでもゲーム側のコードは変わりません。

    IGripInputProvider
    using MS2026.GripInputBridge;

var p = GripInputBridge.Provider;   // 未初期化ならキーボードシミュレータを自動生成
float grip = p.GetGripValue(playerIndex);   // 0-1（ゲームが使う値）
float raw  = p.GetRawValue(playerIndex);    // フィルタ・較正前
bool  on   = p.IsGripping(playerIndex);     // 12%/8% のヒステリシス判定
var   st   = p.GetStatus(playerIndex);      // Connected / Disconnected

p.OnGripStarted  += i => { /* 握り始めの瞬間 */ };
p.OnGripReleased += i => { /* 離した瞬間 */ };
    更新非表示の GripInputBridgeRuntimeDriver（実行順 -1000）が自動生成され、毎フレーム 1 回だけサンプリング。同フレーム内の読み取りは同じ値。
    使用箇所LaserTurret（Fortress）が IsGripping と GetGripValue を毎フレーム読む。ネット対戦中は TurretNetworkHub が、どの PC でもセンサー 1 番（番号 0）を自分の砲台の入力として読む。
    Transports
    using MS2026.GripInputBridge;
using MS2026.GripInputBridge.Transports;
using MS2026.GripInputBridge.Recording;

GripInputBridge.SetTransport(GripInputBridge.Simulator);            // キーボード（全体で 1 つの共有インスタンス）
var serial = new SerialGripTransport(deviceConfig);                 // 実機（要 define）
if (serial.IsPortOpen)                                              // 開けなかったら差し替えない
    GripInputBridge.SetTransport(new CompositeGripTransport(serial, GripInputBridge.Simulator)); // 実機＋キーボード
GripInputBridge.SetTransport(new ReplayGripTransport(path));         // 記録再生

// LAN で配る（展示）: ArduinoSerialReader が -grip-sensor N を見て自動で行う
var relay = new GripRelaySession(GripRelayOptions.Parse(args), 0.5, 60f);   // 受け取り＋放送係
GripInputBridge.SetTransport(relay.Transport);  // P1 = センサー N（この PC の Arduino → 無ければ放送）＋Q
relay.SetLocalDevice(serial);                   // この PC に Arduino があれば放送する（無くなったら null）

GripInputBridge.SetCalibrationProfiles(profiles);   // 4 人分（null は既定）
GripInputBridge.SetFilterSettings(filterSettings);  // 未呼び出しなら素通し
GripInputBridge.StartRecording();  /* ... */  GripInputBridge.StopRecording();
    注意SerialGripTransport は差し替え時に Dispose() 必須（COM ポート解放）。#if MS2026_GRIP_SERIAL_ENABLED 内。入力元は全体で 1 つ（最後に設定した人が勝つ）ので、元に戻すときは GripInputBridge.CurrentTransport が自分の設定したものか確かめてから戻す。ポートの自動さがしは SerialGripPortSearch（候補を別スレッドで同時に開き、最初に値が届いたポートを選ぶ）と GripPortCandidates.Build（試す順番。テストあり）。
    LANRuntime/Relay/：放送の形 GripRelayCodec、受け取った値 GripRelayReceiverState（放送が 2 か所なら先の方。止まった・値が無いときはもう一方へ）、起動オプション GripRelayOptions、送受信 UdpGripRelaySender／UdpGripRelayReceiver（専用スレッド。本物の UDP のテストあり）、P1 にする RelayedSensorTransport。ゲーム側（砲台の通信・キャラ選択・タイトル）は変えていない。
