    GRIP INPUT握力入力ブリッジ

    Grip Input Bridge ＆ Simulator — 握力センサーとゲームのあいだの通訳

    センサーの「生の値」を、
    ゲームが使える 0〜100% の握力 に整える。
    センサーが無くても キーボードで動く。

    センサーは個体差もノイズもあるし、子どもと大人で握力も全然違います。それを毎回「この人にとっての 0〜100%」に通訳してゲームに渡すのがこのツールです。ゲーム側は通訳済みの数字だけを見ればいい、という仕組みです。

    誰が使う
    全員（開発中のテスト）／本番当日の運営スタッフ（キャリブレーション・監視）
    開き方
    Tools›握力入力ブリッジ›ウィンドウを開く
    キー
    P1 Q　P2 W　P3 O　P4 P（押しっぱなしで握力が上がる）
    ウィンドウ無しでも
    Play するだけでキーボード入力は自動で有効。ウィンドウは「見る・調整する」ための道具です
    01 — What it does

    握った力が
    ゲームに届くまで。

    握力は次の順番で「通訳」されて、最後にゲーム（砲台のレーザー）へ届きます。どの段階も、このツールで確認・調整できます。

    FROM HAND TO LASER
    1 · 入力元
    センサー or キーボード or 記録
    どこから値を取るか。いつでも切り替えられる。
    2 · ノイズ除去
    ガタつきを取る
    一瞬だけ跳ねた値などをならす（設定した場合）。
    3 · キャリブレーション
    その人の 0〜100% に
    その人の最大握力を 100% として換算。子どもも大人も対等に。
    4 · 判定
    握った／離した
    12% を超えたら「握った」、8% を下回ったら「離した」。
    5 · ゲーム
    レーザーの太さ・熱
    砲台がこの 0〜100% を毎フレーム読む。
    ⌨️

    シミュレータ

    キーボードで 4 人分の握力を代用。押すと上がり、離すと下がる「握ってる感じ」の動き。

    使う場面 センサーが無い普段の開発

    〰️

    波形プリセット

    「そっと／しっかり／渾身／リズムテスト」の握り方を自動で再生。手を使わずに試せる。

    使う場面 渾身で何秒でオーバーヒートするか見る

    🎯

    キャリブレーション

    プレイヤーごとに 3 秒全力で握ってもらい、その人の 100% を記録する。

    使う場面 本番で来場者ごとに

    🩺

    診断

    4 人分の接続状態と現在の値を一覧。ケーブル抜けなどにすぐ気づける。

    使う場面 展示本番の監視

    ⏺️

    記録と再生

    握力の動きをファイルに記録して、あとで同じ動きを再生できる。

    使う場面 本番で起きた不具合の再現

    🔌

    実機（Arduino）

    USB でつないだマイコンのセンサー値を受け取る。最大 4 人分。

    使う場面 筐体での実プレイ

    03 — Recipes

    「〜したい」から
    探す。

    4 人同時に握った状態を試したいシミュレータ

    QWOP を同時に押しっぱなしにします。手が足りなければ、何人かを 波形プリセット（そっと／しっかり／渾身）にして自動で握らせます。

    「そっと」「しっかり」「渾身」の強さで試したいシミュレータ
    • そっと：20〜30% をゆらゆら維持
    • しっかり：50〜60% を維持
    • 渾身：90〜100% を維持（オーバーヒートの確認に）
    • リズムテスト：0.4 秒ごとに 80% と 0% を交互に（握る／離すの繰り返し）

    なし(キーボード操作) に戻すとキー入力に戻ります。

    本番で来場者ごとにキャリブレーションしたいキャリブレーション
    1. Play 中に「キャリブレーション」タブを開く。
    2. プレイヤー で P1〜P4 を選ぶ。
    3. 計測開始(3秒間、最大握力で握ってください) を押し、カウントダウンの間ずっと全力で握ってもらう。
    4. 「計測結果(最大値): 0.xxx」が出たら この結果を保存。

    これでその人の全力が 100% になり、握力が弱い人でも太いレーザーが出せるようになります。

    !
    今の仕様の注意：保存した結果は「保存したその Play の間」だけ反映されます。Play をやり直したときや、ビルドしたゲームでは自動で読み込まれません（読み込みはまだ未実装）。その都度キャリブレーションし直してください。
    本番中にセンサーが抜けていないか見張りたい診断

    「診断」タブに 4 人分の 状態 と 現在の値 が並びます。Connected 以外（Disconnected など）が出たら要確認。実機は、一定時間（設定では 200ms、Arduino 用コンポーネントでは 1000ms）データが来ないと「切断」とみなします。

    センサーが壊れたので、その人だけキーボードで代用したい入力元

    上部の 入力元 を シミュレータ に切り替えると、Play を止めずに全員キーボード入力になります（切り替えは 4 人まとめて）。実機に戻すときは 実機 を選び直します。

    プレイ中の握力の動きを記録して、あとで再現したいREC / 記録再生
    1. 上部の ● REC を押すと記録開始（ボタンが ■ 停止 に変わる）。保存先は Console に表示されます。
    2. もう一度押すと記録終了。ファイルはプロジェクト直下の GripLogs/日付_時刻_session.jsonl。
    3. 再現するときは 入力元 を 記録再生 にして、そのファイルを選ぶ。記録したときと同じタイミングで握力が再生されます。

    再生されるのは「通訳前の生の値」なので、キャリブレーションや設定を変えて「同じ握り方で結果がどう変わるか」を比べられます。

    Arduino のセンサーをつなぎたい実機
    1. Arduino IDE の シリアルモニタは閉じる（開いているとポートを取り合って Unity から読めません）。
    2. シーンの適当な GameObject に ArduinoSerialReader コンポーネントを付ける。
    3. Port Name に COM ポート（Arduino IDE の「ツール › ポート」で確認、例 COM3）、Baud Rate にスケッチの Serial.begin(…) と同じ値（既定 9600）。
    4. 磁石で反応するホールセンサー（49E など）なら Centered Sensor を ON（何もしていないとき約 512 を出すタイプ）。
    5. ▶ Play。Log Values が ON なら Console に P1: arduino=… raw=… grip=… が流れます。

    実機につないでいる間もキーボード（Q/W/O/P）は効きます。COM ポートを開けなかったとき（デバイスを挿していない等）は「キーボードシミュレータのまま動かします」と警告が出て、キーボードだけで遊べます（デバイスが無い PC でも同じビルドが使えます）。

    Arduino からは Serial.println(analogRead(A0)); のように 1 行に数値 1 つ（P1）、または 512,300 のように カンマ区切りで最大 4 つ（P1〜P4）を送れば OK です。

    何もしていないのに「握っている」になる実機
    • ホールセンサーなら Centered Sensor が ON か確認。OFF だと、何もしていないときの約 50% をそのまま握力と勘違いします。
    • ON なのにずれるなら、Sensor Center 01（何もしていないときの値。Uno の 512 なら 0.5）を Console の arduino= の値 ÷ 1023 に合わせます。
    • 小さなノイズは 3% 以下を 0 とみなす「デッドゾーン」で吸収しています。
    ウィンドウの「入力元：実機」を使いたい入力元

    ウィンドウの 実機 は、プロジェクト内の GripDeviceConfig アセットの設定で接続します。まだ無いので、Project ウィンドウで右クリック › Create›MS2026›Grip Input Bridge›Device Config で作り、Serial Port Name・Baud Rate（既定 115200）などを設定してください。普段の配線テストは上の ArduinoSerialReader の方が手軽です。

    見つかりませんでした。別の言葉で探してください。

    04 — Every tab

    タブごとの
    役割。

    上部バー（常に表示）

    ⏱ 握力をどこから取るか決めるとき
    • 入力元：シミュレータ（キーボード・波形）／実機（GripDeviceConfig の設定でシリアル接続。キーボードも併用可）／記録再生（ファイルを選ぶ）。Play を止めずに切り替えられます。実機につなげなかったときは、確認画面が出て今の入力元のままになります。
    • ● REC：記録の開始／停止。
    i
    ウィンドウを開いただけでは入力元は変わりません。シーンの ArduinoSerialReader が実機につないでいれば「実機」と表示されます。「実機」のときもキーボード（Q/W/O/P）と波形プリセットは使えます（実機とキーボードの大きい方が使われる）。

    シミュレータ

    ⏱ 普段の開発・テスト
    • P1〜P4 の 接続状態の点（色付き=接続中／灰色=未接続）、状態、握力バー（0〜100%、ゲームが実際に使う値）。
    • 波形プリセット：なし(キーボード操作)／そっと／しっかり／渾身／リズムテスト。
    • キーボード操作キー の表示（P1=Q、P2=W、P3=O、P4=P）。

    キャリブレーション

    ⏱ 本番で来場者が替わるたび（Play 中のみ）
    • プレイヤー：P1〜P4 を選ぶ。
    • 計測開始(3秒間、最大握力で握ってください)：3 秒のカウントダウン中の最大値を記録。
    • この結果を保存：Assets/_Tools/GripInputBridge/CalibrationProfiles/P1_CalibrationProfile.asset などに保存して、すぐ反映。

    診断

    ⏱ 展示本番中の見張り
    • 4 人分の 状態（Connected / Disconnected）と 現在の値 の一覧。入力元が実機のときは「実機 接続中」／「実機なし(キーボード)」と表示され、実機が来ていない人の行が警告色になります。
    • Connected 以外が出たら、ケーブル・電源・COM ポートを確認。
    05 — Numbers

    知っておくと
    話が早い数字。

    ⌨️ シミュレータと判定 コード内の既定値
    項目意味メモ値
    上がる速さキーを押している間、1 秒に上がる量0% → 100% まで約 0.33 秒3.0 / 秒
    下がる速さ離している間、1 秒に下がる量100% → 0% まで約 0.67 秒1.5 / 秒
    「握った」判定この値を超えたら握り始め「離した」との間にのりしろがある12%
    「離した」判定この値を下回ったら離した8%
    デッドゾーンこれ以下は 0% とみなすセンサーの小さなノイズを無視するため3%
    🔌 実機の設定 ArduinoSerialReader コンポーネント ／ GripDeviceConfig アセット
    項目意味メモ既定
    Port NameCOM ポート名デバイスマネージャー／Arduino IDE で確認COM3
    Baud Rate通信速度Arduino 側と同じにする9600 ／ 115200
    Heartbeat Timeout Msこの時間データが来ないと「切断」Arduino の送信間隔より長く1000 ／ 200
    Centered Sensor中心からの距離を握力にするホールセンサー（49E 等）は ONON ／ OFF
    Sensor Center 01何もしていないときの値（0〜1）Uno の 512 なら 0.50.5

    「既定」が 2 つあるものは「ArduinoSerialReader ／ GripDeviceConfig」の順。

    06 — Troubleshooting

    困ったときは
    ここ。

    キーを押してもバーが上がらない
    1. Play 中か確認（Play していないと動きません）。
    2. Game ビューをクリックしてから押す。
    3. その人の 波形プリセット が「なし(キーボード操作)」になっているか（プリセット中はキーを無視）。
    4. 入力元 がシミュレータか実機か確認（記録再生中はキーが効きません）。
    実機の値が来ない（Disconnected のまま）
    1. Arduino IDE のシリアルモニタを閉じる（ポートの取り合い）。
    2. COM ポート名とボーレートが Arduino 側と一致しているか。
    3. Console に「シリアルポート 'COM3' を開けませんでした」が出ていないか。
    4. 前の Play がポートを掴んだままのことがあります。Play を止めてもう一度 Play、それでもダメなら Unity を再起動。
    5. Console に「キーボードシミュレータのまま動かします」と出ていたら、ポートを開けていません（上の 1〜3 を確認）。
    Console に「実機通信が無効のため…」と出る
    実機通信には Project Settings › Player › Api Compatibility Level を「.NET Framework」、Scripting Define Symbols に MS2026_GRIP_SERIAL_ENABLED が必要です。このプロジェクトでは Standalone（PC）向けに設定済みなので、別のビルド対象に切り替えていないか確認してください。設定の変更はプログラマーに相談を。
    キャリブレーションしたのに、次に Play したら元に戻った
    今の仕様です。保存したファイルは残りますが、次の Play では自動で読み込まれません。もう一度キャリブレーションするか、プログラマーに「起動時に読み込む処理」を追加してもらってください。
    値がガタガタ震える
    ノイズ除去の設定ファイル（GripFilterSettings）は用意されていますが、今は使われていません（何も通さずにそのまま値が届いている状態）。ガタつきが気になる場合は、プログラマーにフィルタ設定の適用を依頼してください（おすすめは既定の「メディアン → EMA」）。
    07 — Words

    分からない言葉は
    ここで引く。

    生の値 raw
    センサーから来たままの値（0〜1 に換算済み）。人によって最大値がばらばら。
    握力値 grip value
    通訳後の 0〜100%（0〜1）。ゲームが使うのはこれ。
    キャリブレーション
    その人の全力を測って 100% に合わせること。較正とも言う。
    デッドゾーン
    ごく小さい値を 0 とみなす範囲。ノイズで勝手に握った判定にならないように。
    のりしろ ヒステリシス
    「握った」と「離した」の境目をずらしておくこと。境目でふらついても判定がバタつかない。
    入力元 トランスポート
    値をどこから取るか。シミュレータ・実機・記録再生の 3 種類。
    COM ポート
    USB でつないだマイコンに Windows が付ける番号（COM3 など）。
    ボーレート
    シリアル通信の速さ。送る側と受ける側で同じにしないと読めない。
    ハートビート
    「生きてるよ」の定期的なデータ。一定時間途切れたら切断とみなす。
    ホールセンサー
    磁石の近さで値が変わるセンサー。何もしないと中間の値を出す。
    08 — For programmers

    ゲームから読むのは
    この 1 行。

    入口は静的クラス MS2026.GripInputBridge.GripInputBridge だけ。実機・シミュレータ・記録再生のどれでもゲーム側のコードは変わりません。

    IGripInputProvider
    using MS2026.GripInputBridge;

var p = GripInputBridge.Provider;   // 未初期化ならキーボードシミュレータを自動生成
float grip = p.GetGripValue(playerIndex);   // 0-1（ゲームが使う値）
float raw  = p.GetRawValue(playerIndex);    // フィルタ・較正前
bool  on   = p.IsGripping(playerIndex);     // 12%/8% のヒステリシス判定
var   st   = p.GetStatus(playerIndex);      // Connected / Disconnected

p.OnGripStarted  += i => { /* 握り始めの瞬間 */ };
p.OnGripReleased += i => { /* 離した瞬間 */ };
    更新非表示の GripInputBridgeRuntimeDriver（実行順 -1000）が自動生成され、毎フレーム 1 回だけサンプリング。同フレーム内の読み取りは同じ値。
    使用箇所LaserTurret（Fortress）が IsGripping と GetGripValue を毎フレーム読む。ネット対戦中は TurretNetworkHub が、どの PC でもセンサー 1 番（番号 0）を自分の砲台の入力として読む。
    Transports
    using MS2026.GripInputBridge;
using MS2026.GripInputBridge.Transports;
using MS2026.GripInputBridge.Recording;

GripInputBridge.SetTransport(GripInputBridge.Simulator);            // キーボード（全体で 1 つの共有インスタンス）
var serial = new SerialGripTransport(deviceConfig);                 // 実機（要 define）
if (serial.IsPortOpen)                                              // 開けなかったら差し替えない
    GripInputBridge.SetTransport(new CompositeGripTransport(serial, GripInputBridge.Simulator)); // 実機＋キーボード
GripInputBridge.SetTransport(new ReplayGripTransport(path));         // 記録再生

GripInputBridge.SetCalibrationProfiles(profiles);   // 4 人分（null は既定）
GripInputBridge.SetFilterSettings(filterSettings);  // 未呼び出しなら素通し
GripInputBridge.StartRecording();  /* ... */  GripInputBridge.StopRecording();
    注意SerialGripTransport は差し替え時に Dispose() 必須（COM ポート解放）。#if MS2026_GRIP_SERIAL_ENABLED 内。入力元は全体で 1 つ（最後に設定した人が勝つ）ので、元に戻すときは GripInputBridge.CurrentTransport が自分の設定したものか確かめてから戻す。
    詳細Docs/Tools/GripInputBridge_AI_Reference.md。設計意図は GripInputBridge_設計仕様書.md。
    1 行 = 1 サンプル（"\n" 区切り）
    512                 ← 0-1023 の整数 1 つ = P1
512,300             ← カンマ区切り最大 4 つ = P1, P2, ...
G,0,2048,183920     ← 正式形式: G,プレイヤー(0-3),値(0-4095),機器時刻ms
    堅牢性化けた行は捨てて通信を続ける。受信は別スレッド、値は Volatile で受け渡し。
