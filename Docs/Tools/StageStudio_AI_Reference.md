## 0. Mental model
- The game map is the **XY plane at z=0**; the camera looks down **+Z**; "up from the floor" is **−Z** (toward the camera). Maya is Y-up, so imported models are rotated `Euler(-90,0,0)` (option `Mayaの向きを床に合わせる`).
- A **stage** = `StageSet` asset (ScriptableObject) → a **stage prefab** (root with a `Props` child) + `CameraViewPreset` + `StageLookProfile` + lighting + optional D-Drive BGM. Several stages can exist; one is "placed" in the scene under a **`StageRoot`** (`[Stage]` GameObject) as a **prefab instance**. Edits in the scene are written back with `ステージに保存` (= `PrefabUtility.ApplyPrefabInstance`).
- A **background object** = `StageProp` root (only Z rotation allowed) with children `Visual` (wobble pivot, holds the model) and `Footprint` (`PolygonCollider2D` + `StagePropFootprint`). Enemies avoid it because the root also has `NavigationObstacle` (existing Fortress component) which rasterizes the child collider into the flow-field grid; the swarm's wall SDF is built from that grid, so the "liquid flows around the shampoo" behaviour needs **no swarm changes**.
- The footprint is generated in the editor from the mesh: triangles below `blockHeight` are projected to the floor, rasterized, holes filled, gaps closed, padded, traced to polygons and simplified (`FootprintBuilder`). Parts floating higher than `blockHeight` can be walked under.
- All visual reactions are **local per PC, no networking**: holes/fade where a prop hides turrets/core (shader), hidden-enemy silhouettes (swarm shader stencil pass), laser heat glow + scorch, wobble from swarm pressure, dissolve when a destructible prop breaks. Destructible state itself is synced by the existing `DestructibleNetworkHub` because destructible props are ordinary `DestructibleObstacle`s.

## 2. Runtime API
- `StageProp` (`[ExecuteAlways]`, `[SelectionBase]` so a scene click on the model selects the prop root): `role`, `laserPassesThrough`, `slowZoneSpeed=0.5`, `slowZoneAvoidance=3`, `look` (`StagePropLookSettings`), `visualRoot`, `modelRoot`, `sourceModel` (asset), `sourceNodePath`, `footprint`, `memo`; static `All`; `BlocksLaser`; `VisualBounds` (allocates — editor use); `ApplyRoleState()` sets `NavigationObstacle.enabled/mode/speed/cost` and collider `enabled/isTrigger` per role (skipped for `DestructibleWall`, where `DestructibleCollision` owns them). Called from `OnEnable`/`OnValidate`.
- Roles `StagePropRole { Decoration, Floor, Wall, DestructibleWall, SlowZone }` (labels 飾り/床/壁/壊せる壁/遅くなる地帯). `NeedsFootprint` = Wall/DestructibleWall/SlowZone. Laser passes through triggers (`LaserBeamVisual` uses `useTriggers=false`): SlowZone and Wall+`laserPassesThrough` make the footprint a trigger. Nav still blocks (OverlapPoint ignores trigger state).
- `StagePropFootprint` (on `Footprint`, RequireComponent `PolygonCollider2D`): `settings` (`FootprintSettings`), `manuallyEdited`, `Collider`, `HasShape`, `BuiltVertexCount/BuiltArea/BuiltCellSize`, `IsStale(modelRoot)` (signature of meshes+matrices+settings), `Rebuild(modelRoot) → FootprintBuilder.Report` (editor; non-readable meshes are fine in the editor only), `ApplyPaths(paths)` (calls `NavigationObstacle.NotifyChanged`).
- `FootprintSettings` defaults: `blockHeight 0.6, padding 0.05, closeGaps 0.1, resolution 0.05, simplify 0.04, fillHoles true, minArea 0.02` (`FootprintBuilder.MaxCellsPerSide = 512` coarsens the grid for big models).
- `FootprintBuilder.Build(vertices, triangles, settings, out Report)`; vertices are in footprint-local space (XY floor, height = −z). Conservative raster: thin (≈ zero-area, e.g. vertical walls) polygons are tested against the full cell, others against 0.35×cell. Outer loops CCW, holes CW; diagonal-only contacts become separate loops (left-turn preference).
- `FootprintGeometry.ClosestPoints/Contains/SegmentDistance` (pure, used by the gap finder).
- `StagePropRenderer`: owns `StagePropLook Look` (Fade, NoHole, Darken, Flash, FlashColor, Dissolve, DissolveColor, HeatPoints[8], HeatValues[8], HeatCount); modules write it and call `MarkDirty()`; `LateUpdate` writes one `MaterialPropertyBlock` to all renderers under `visualRoot`, or clears it when `Look.IsNeutral` (keeps SRP Batcher). `CollectRenderers()`, `ComputeBounds()`, `SetVisible(bool)`.
- `StageFocusPoints` (`[ExecuteAlways]`, on StageRoot): every LateUpdate collects `CoreCrystalController` + `LaserTurret`s (re-found every 1 s), lifts them by `focusHeight` (−Z), radius `coreHoleRadius`/`turretHoleRadius` (local player's turret × `localTurretHoleScale`; local player = `FortressCameraRig.Active.CurrentViewer`, else `FortressNetworkBootstrap.LocalPlayerIndex`), sets globals `_StageFocusPoints[8]`, `_StageFocusCount`, then `StageLookProfile.ApplyGlobals()`.
- `StageLaserHeatScanner` (on StageRoot): LateUpdate over `LaserBeamVisual.Active` with `HasImpact` → `ImpactCollider.GetComponentInParent<StagePropHeat>()` → `ReceiveLaser(ImpactPoint − heatHeightOffset·Z, turret.CurrentThicknessMeters, dt)`. Works on clients because they raycast locally.
- `StagePropHeat`: `HeatPointBuffer` (8 points; merge within 0.3+r/2; glow += `glowPerSecond·heatScale·dt`; cools `coolPerSecond`; scorch += glow·`scorchPerSecond`; scorch never cools; full → replaces weakest). `ClearMarks()`.
- `StageSwarmPressure` (on StageRoot): subscribes `SwarmSystem.Current.StorageReadable`; for each registered `StagePropWobble` sums `SwarmSpatialGrid.CountInCell` over the footprint bounds + `pressureRange` → `Sample{Count, Direction}`. No job, main thread, cheap.
- `StagePropWobble` (Play only): target tilt = −dir·clamp01(count/`pressureForFullTilt`)·`maxTiltDegrees`·`wobbleStrength`; kick on sudden surges; `DampedSpring2D` (`stiffness`, `damping`, substeps 1/120 s); rotates/squashes `visualRoot` around the floor pivot (directions converted to root-local). `Poke(dir, degrees)`, `CurrentTilt`, `LastPressure`.
- `StagePropOcclusion`: sets `Look.NoHole` unless mode is `Hole` (floors never get holes); `WholeFade` mode fades to `1−wholeFadeAlpha` when a focus→camera ray hits the renderer bounds (ortho uses camera back vector).
- `StagePropDestructibleView` (only when a `DestructibleObstacle` is present): Damaged→flash, HealthChanged→darken (`darkenAtZeroHealth`), Destroyed→dissolve 0→1 over `dissolveSeconds` then hide renderers, Regenerated→show + dissolve 1→0 + clear scorch. `SnapToState()` on enable (late join).
- `StageRoot` (`[ExecuteAlways]`, RequireComponent FocusPoints/HeatScanner/SwarmPressure): `current`, `instance`, `sun`, `playBgmOnStart=true`; static `Active`; `LookProfile`; `ApplyEnvironment(applyCamera)` (lighting → `[Stage] Sun` child Directional Light, globals, and `rig.preset` / `rig.SetPreset` when applyCamera); `Start` (Play) applies lighting and plays `bgm` after `DDriveRuntimeBootstrap.Instance.IsReady` (10 s timeout); `bool SwitchAtRuntime(StageSet)` (Instantiate; returns false and logs a warning while `FortressNet.IsNetworked`, because DestructibleNetIndex is built at connect time and would desync); `EnsureSun()`.
- `StageLookProfile` (`Create › Stage › Stage Look Profile`), `StageLookProfile.Current` (StageRoot's profile or a hidden default instance). Fields/defaults: turretHoleRadius 1.6, coreHoleRadius 2.4, localTurretHoleScale 1.3, holeSoftness 0.4, focusHeight 0.4, wholeFadeSpeed 6, showHiddenEnemies true, hiddenEnemyColor (0.35,0.9,1,0.55), glowPerSecond 2.5, coolPerSecond 0.7, scorchPerSecond 0.3, heatRadius 0.35, heatRadiusPerThickness 0.8, heatHeightOffset 0.15, glowColor/hotColor (HDR), scorchColor, pressureForFullTilt 25, maxTiltDegrees 5, squash 0.04, stiffness 90, damping 7, pressureRange 0.8, hitFlashColor, hitFlashSeconds 0.08, darkenAtZeroHealth 0.45, dissolveSeconds 0.7, dissolveEdgeColor.
- `StageSet` (`Create › Stage › Stage Set`, normally created by the tool): displayName, memo, thumbnail, stagePrefab, cameraPreset, lookProfile, lighting (`StageLightingSettings`: apply, sunColor, sunIntensity 1.2, sunDirection −35°, sunElevation 55°, shadowStrength 0.6, sky/equator/ground colors (Trilight ambient), fog/fogColor/fogStart 20/fogEnd 60), `bgm` (`AssetId<BgmMarker>`).

## 3. Shaders
- `MS2026/Stage/Prop`: URP Lit property names (drop-in for Lit materials), forward pass `UniversalForwardOnly` (custom fragment = URP `LitPassFragment` + `StageClip` + `StageModifySurface`), `UsePass` Lit ShadowCaster/DepthOnly/DepthNormals/Meta (so holes don't affect shadows/depth; fine because PC renderer is Forward+ with depth priming off). Stencil: writes bit 64 with `Ref [_StencilRef]` (64 = "hidden enemies show here", 0 = floor/no mark). Keyword `_STAGE_NO_HOLES` (material toggle `_StageNoHoles`) for floors. CustomEditor `StagePropShaderGUI` (auto keywords `_NORMALMAP/_METALLICSPECGLOSSMAP/_OCCLUSIONMAP/_ALPHATEST_ON/_EMISSION/_STAGE_NO_HOLES`).
- Holes: per pixel, distance from the focus→camera line (ortho: along `UNITY_MATRIX_V[2]`) < radius and pixel in front of the focus → dithered clip (Bayer 4×4, softness `_StageHoleSoftness·radius`). Fade uses the same dither. Dissolve uses 3D value noise ×3; heat glow/scorch from the per-renderer point arrays.
- Per-renderer values are plain uniforms set through MPB; all default to 0 = no effect (so materials render normally without StageRoot).
- `MS2026/Fortress/SwarmSilhouette` (ZTest Greater, ZWrite Off, stencil Equal 64 ReadMask 64) draws `_FortressSilhouetteColor` where a prop with the stencil mark is in front of an enemy. `SwarmRenderer` only issues this extra draw while global `_FortressSilhouetteEnabled` > 0 (`StageLookProfile.ApplyGlobals` sets it from `showHiddenEnemies`; `StageRoot.OnDisable` resets it to 0), so scenes without a stage pay nothing.

- `StagePropHandles` (on the first selected prop, applied to all): ring `Handles.Disc` around +Z at root, radius `max(0.4, 1.1·max(extents.xy))`, snap `AngleStep`, rotation applied as delta to each prop's own yaw, collapsed to one undo (`背景を回す`) when hot control is released. Scale knob (cube at ring 315°): floor-ray distance ratio → `StagePropTransformOps.ScaleModel` incrementally, snapped to 0.05; label `×1.20（幅 … × 奥行 … × 高さ … m）`. Lift pill (GUI rect right of the top point, text `↕ 床の上` / `↕ 0.40m 浮き` / `↕ 0.40m 沈み`): vertical mouse delta × `GetHandleSize(top)/120` m/px (Shift ×0.2), snapped to 0.05 (or to 0 within 0.03 when not snapping) → `SetLift`.
- `StagePropTransformOps` (Undo-aware): `Model(prop)` (= modelRoot ?? visualRoot ?? root), `Lift(prop)` = `root.z − VisualBounds.max.z` (up is −Z; negative = sunk), `Size`, `Move`, `SetYaw/Yaw`, `ScaleModel(prop, factor)` (scales **the model**, about the root floor point; root scale stays 1 so footprint padding etc. stay metric), `SetLift(prop, lift)` (moves the model along Z), `Commit()`. Scale/lift call `StageFootprintRefresher.Request` (debounced 0.15 s rebuild via `StagePropComposer.RebuildFootprint`; `Flush()` on release; `manuallyEdited` footprints are not rebuilt — their paths are scaled by the factor about the root instead).
- `StagePlaceSettings` (EditorPrefs `MS2026.StageStudio.Place.*`, per PC): `Snap` true, `GridStep` 0.25, `AngleStep` 15, `EdgeSnapDistance` 0.2 (0 = off), `ShowDistances` true, `NearWarning` 1.0, const `DistanceRange` 8, `ParallaxViewer` 0 (P1; `ParallaxOff` = −99), `ParallaxForAll` false, `AutoTool` true, `PreviewViewer` 0, `PreviewQuad` false, `PreviewOutlines` true.
- `StageGamePreview`: hidden HideAndDontSave camera, `Render(viewer, width, height)` (`CopyFrom(rig.targetCamera ?? Camera.main)`, `CameraPoseApplier.Apply`, aspect = width/height, URP `RenderPipeline.SubmitRenderRequest`), `Texture`, `Camera` (pose of the last render; used for picking/projection).
- `StageGameCamera` (`[InitializeOnLoad]`): `Preset` (rig.preset, else current StageSet.cameraPreset), `Rig`, `Aspect` (`Handles.GetMainGameViewSize`, fallback 16:9), `TryGetView/TryGetPose(viewer)`, `HasParallax(view)` (= perspective or tilt > 0), `Version` + `MarkDirty()` (bumped by `ObjectChangeEvents.changesPublished`, undo/redo and every edit; previews re-render only when it changes).
- `StageSceneViewSync`: `Lock(viewer, view?)` sets `orthographic`, `cameraSettings.fieldOfView`, `LookAtDirect(center, pose rotation, size)`; every Layout it compares the rendered scene camera with the target and corrects (FOV setting += error; size ×= target distance / `cameraDistance`, or × ortho size ratio) — empirically Unity 6000.3 scene camera vertical FOV = setting and `cameraDistance = size / sin(fov/2)`, and FOV settings > 120 are accepted. Any user change of pivot/rotation/size unlocks. `DrawGameFrame` (from StageSceneOverlay, Repaint) darkens outside the Game-view aspect frame + banner `プレイヤーNのゲーム目線（回す・ずらす・拡大で解除）`.
- `StageParallaxGuide.Draw` (from StageSceneOverlay): for selected props (or all with `ParallaxForAll`, Floor role skipped) and the chosen viewer with parallax: model vertices (≤600 sampled per mesh, cached per Mesh; skinned → bounds corners), points below floor clamped to z=0, projected from the camera onto z=0 (`StagePlaceMath.ProjectToFloor`; ortho uses camera forward) → convex hull drawn filled (player colour α0.16) + dotted outline; arrow from the floor point under the top-center to its projection with `P1では 1.6m ずれて見える` (hidden < 0.05 m). `TopShift(prop, viewer)` is used by the `配置` side panel.
- `StageDistanceGuide.Measure(prop) → List<Reading{Label, Target, Closest, Distance, Overlaps, TooClose, Text}>` (sorted, ≤ 8 m) is shared by the page; `Draw` (scene view): targets (turrets `P{n}の砲台`, `コア`, `湧き位置`, rescanned every 1 s) within 8 m of the selected props' footprint paths (visual-bounds rect when no footprint) → dotted line + `… 1.8m` / `… 0.6m 近すぎ` (red, < `NearWarning`) / `…に重なっています`.
- `StagePlaceMath` (pure): `SnapValue`, `SnapToGrid`, `EdgeSnap(Rect, IReadOnlyList<Rect>, threshold) → EdgeSnapResult{Offset, SnappedX/Y, GuideX/Y}`, `ProjectToFloor(point, camPos, camForward, ortho, out Vector2)`, `ConvexHull` (CCW), `DistanceToPolygon` (0 inside), `BoundsOf`.

## 5. Integration
- Uses Fortress: `NavigationObstacle`, `NavigationField`, `DestructibleObstacle` family, `LaserBeamVisual`, `LaserTurret`, `CoreCrystalController`, `EnemySpawnPoint`, `SwarmSystem` (grid + `StorageReadable`), `FortressCameraRig`/`CameraViewPreset`/`CameraViewMath`, `FortressNetworkBootstrap`. Fortress does **not** reference Stage.
- D-Drive: only `StageSet.bgm` (`Audio.PlayBgm`). Destructible prop effects use the existing `FortressEffect` slots of `DestructibleObstacle.settings.feedback` (project rule).
- Multiplayer: nothing new is sent. Stage must be placed in the scene before connecting (it's part of the scene). Destructible props replicate through `DestructibleNetworkHub` like any destructible.

## 6. Gotchas
1. Prop roots must only rotate around Z (2D colliders ignore X/Y rotation); rotate the model under `Visual` instead. The check `根元が傾いています` fixes it.
2. Footprint generation reads meshes in the editor; at runtime only the stored `PolygonCollider2D` is used (no Read/Write needed). Splitting imports makes unlinked copies → after changing the FBX use `取り込み直す` (keeps pose; node moves made in Maya are not reapplied).
3. `NavigationField.cellSize` (default 0.5) decides whether a narrow gap exists for pathfinding at all; the gap ruler shows red when the midpoint cell is blocked.
4. Holes/silhouettes need materials on `MS2026/Stage/Prop`; silhouettes need prop materials with stencil 64 and the swarm shader (any material using another shader neither writes the mark nor gets holes).
5. Changing `見た目の反応 › 裏に隠れた敵を影で見せる` requires `専用シェーダーに切り替え` again (it picks the `_NoMark` copy).
6. `StageRoot.SwitchAtRuntime` refuses while connected (see §2). Switching stages mid-match needs a synchronized switch + rebuilding the destructible index — not implemented (multiplayer homework).
9. A new stage only contains background props: turrets, core, spawn points, NavigationField, SwarmSystem and existing obstacles stay in the scene untouched. Placing a stage applies its lighting (`lighting.apply` defaults to true): Trilight ambient + a `[Stage] Sun` directional light, which can double up with an existing Directional Light.
7. Depth priming must stay off (holes are not applied in the Lit depth passes).
8. Unverified in Unity as of 2026-10-06 (see header).
10. Studio windows (Stage & UI) must only dispose their context in `OnDestroy`: `OnDisable` also fires when the window is hidden around Play / layout changes, and disposing there froze the window on "シーンにステージの置き場所がありません" (fixed 2026-10-06; `OnTick` also rebuilds the GUI if the context is missing). Since 2026-10-07 both windows tick from `OnInspectorUpdate` throttled to 0.25 s (+ immediate on `OnFocus`) instead of `rootVisualElement.schedule`, after the notice was reported stuck again when adding a second model.
11. Robustness around the root (2026-10-07): `StageSceneService.CreateRoot` returns the existing `StageRoot` if one is found (never duplicates `[Stage]`); header `CreateStage`/`PlaceSelected` call `context.RecheckNow()` (now also marks props dirty) before `InvalidateAll`; `StagePageBase.UpdateMissingNotice` redraws when the container changes (pages rebuilt by `InvalidateAll`); the Import button re-checks the scene on click and shows a `取り込めません` dialog explaining root missing vs stage not placed instead of silently returning.

11b. Stale root after Play (fixed 2026-10-07): when Play ends Unity rebuilds the scene and the new `StageRoot` can get the **same instance ID** as the destroyed play-mode one. `UnityEngine.Object` `==`/`!=` between two non-null references compares instance IDs only, so `root != Root` was false and the context kept the dead wrapper → `シーンにステージの置き場所がありません` after every Play. `StageStudioContext.Tick` now uses `ReferenceEquals`, and the context re-checks on `EditorApplication.playModeStateChanged` (EnteredEditMode/EnteredPlayMode). Rule for any cached scene object in these studios: compare with `ReferenceEquals` (or just re-assign), never with Unity `!=`. Also note `OnInspectorUpdate` does not fire while Unity is not the focused application, so studio panels only refresh once the user returns to Unity (`CreateGUI` now publishes `StageSceneOverlay.Context` immediately).
12. Scene editing (2026-10-07): scale/lift change the **model under Visual**, never the prop root (root keeps scale 1 so `FootprintSettings` stay in metres and destructible/VFX children aren't scaled). The wobble pivot (Visual) stays on the floor even when the model is lifted. Lift > `blockHeight` removes those parts from the footprint (enemies walk under).
13. The scene-view lock relies on observed SceneView behaviour (FOV/distance formula) and self-corrects each Layout; if a Unity upgrade changes it, the lock still converges but may take a few frames. Synthetic `SceneView.SendEvent` mouse events (used for MCP tests) are offset by the scene-view toolbar height — compute positions from a debug readout, not from `position.height − camera.pixelHeight`.
